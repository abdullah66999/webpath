# Схема контента «Путь веб-разработчика»

Один урок = **два файла** в `content/lessons/`:

- `<lesson-id>.json` — метаданные, примеры, упражнения
- `<lesson-id>.md` — теория урока (Markdown)

Имена файлов ОБЯЗАНЫ совпадать с полем `id`. Теорию можно положить прямо в JSON
полем `body`, но отдельный `.md` удобнее: не нужно экранировать кавычки и
переносы строк. Если `body` в JSON нет — загружается `<id>.md`.

## Файл урока

```jsonc
{
  "id": "css-05-flexbox",              // совпадает с curriculum.json и именем файла
  "stage": "css",                      // id этапа
  "module": "css-layout",              // id модуля
  "order": 5,                          // порядковый номер урока внутри этапа
  "title": "Flexbox: раскладка в одну ось",
  "subtitle": "Как выстроить элементы в ряд или колонку без боли",
  "duration": 15,                      // минуты, оценка на прочтение + упражнения
  "difficulty": "beginner",            // beginner | intermediate | advanced
  "objectives": [                      // 2-5 пунктов, что ученик сможет после урока
    "Объяснить, чем главная ось отличается от поперечной"
  ],
  "keypoints": ["3-6 коротких выводов урока"],
  "examples": [
    {
      "title": "Центрирование карточки",
      "lang": "css",                   // html | css | js | python | bash | json | text
      "code": "…",
      "runnable": true                 // true только для html/css/js (есть live-preview)
    }
  ],
  "exercises": [ /* см. ниже, минимум 2, максимум 4 */ ],
  "resources": ["res-mdn-flexbox"],    // id из content/resources.json
  "next": "css-06-grid"                // id следующего урока или null
}
```

## Markdown в поле `body`

Поддерживается подмножество: `##`/`###` заголовки, `**жирный**`, `*курсив*`,
`` `инлайн-код` ``, fenced-блоки ```lang, списки `-` и `1.`, `> цитата`,
`[текст](url)`, горизонтальная линия `---`, таблицы (строка с `|` и следом
разделитель из дефисов — как в обычном Markdown).
Объём теории: 250–550 слов. Пишем по-русски, на «вы», без воды и без
«в этом уроке мы рассмотрим». Сразу к сути. Термин при первом упоминании
даём на русском и в скобках на английском.

## Упражнения

### 1. `quiz` — тест с одним правильным ответом

```jsonc
{
  "id": "ex1",
  "type": "quiz",
  "prompt": "Какое свойство задаёт главную ось во flex-контейнере?",
  "options": ["align-items", "flex-direction", "justify-content", "gap"],
  "answer": 1,
  "explain": "flex-direction определяет направление главной оси: row или column."
}
```

### 2. `code` — код с автоматической проверкой

Обязательные поля: `lang`, `prompt`, `starter`. Дальше — набор проверок,
зависящий от языка.

**Python** (`"lang": "python"`) — проверки выполняются на сервере:

```jsonc
{
  "id": "ex2",
  "type": "code",
  "lang": "python",
  "prompt": "Напишите функцию square(x), возвращающую квадрат числа.",
  "starter": "def square(x):\n    pass\n",
  "tests": [
    { "kind": "call",   "name": "square", "args": [5],     "expected": 25 },
    { "kind": "call",   "name": "square", "args": [-3],    "expected": 9 },
    { "kind": "stdout", "expected": "готово" },
    { "kind": "raises", "name": "f", "args": [0], "exception": "ZeroDivisionError" }
  ],
  "hints": ["Квадрат — это x * x"],
  "solution": "def square(x):\n    return x * x\n"
}
```

`kind: "call"` — вызывает функцию `name` с `args` и сравнивает результат с
`expected`. `kind: "stdout"` — запускает код целиком и сравнивает стандартный
вывод (построчно, лишние пробелы игнорируются). `kind: "raises"` — ожидает
исключение. `expected` для float сравнивается с допуском 1e-6.

**HTML/CSS/JS** (`"lang": "html" | "css" | "js"`) — проверки в браузере:

```jsonc
{
  "id": "ex3",
  "type": "code",
  "lang": "html",
  "prompt": "Сделайте карточку с заголовком и абзацем.",
  "starter": "<div class=\"card\">\n  \n</div>",
  "fixture": "<style>.card{padding:16px}</style>",   // необязательно: добавляется в preview
  "checks": [
    { "kind": "dom",   "selector": ".card h2", "count": 1 },
    { "kind": "text",  "selector": ".card h2", "contains": "Привет" },
    { "kind": "css",   "selector": ".card", "prop": "display", "equals": "flex" },
    { "kind": "js",    "code": "document.querySelector('.card').children.length === 2" }
  ],
  "hints": ["Заголовок второго уровня — это h2"],
  "solution": "<div class=\"card\"><h2>Привет</h2><p>Мир</p></div>"
}
```

Для `lang: "css"` в preview автоматически подкладывается базовый HTML из поля
`markup` (обязательно для css-упражнений), чтобы было к чему применять стили.
Поле `fixture` — необязательный нейтральный каркас (сброс отступов, шрифт), он
подключается ДО стилей ученика и не должен их перебивать.

Свойства в `kind: "css"` пишите **в camelCase**, как в JS: `justifyContent`,
`backgroundColor`, `flexDirection`. Значения сравниваются с тем, что вернёт
`getComputedStyle`, то есть цвета — в формате `rgb(...)`, а `display: flex`
остаётся `flex`.

`kind: "js"` исполняется в окне предпросмотра и понимает три формы `code`:
голое выражение (`a === b`), несколько инструкций, последняя из которых —
выражение, и тело функции с явным `return`. Все три дают значение, поэтому
`return` писать не обязательно — но и не запрещено.

У `kind: "attr"` значение сравнивается буквально, с учётом регистра.

Для `lang: "html"` документ берётся как есть только если код начинается ровно
с `<!doctype` (регистр не важен) в позиции 0 — тогда `fixture` игнорируется.
Во всех остальных случаях код ученика оборачивается в `<body>`, а `fixture`
подставляется перед ним.

### 3. `task` — задание в реальном инструменте, самопроверка по чек-листу

```jsonc
  "prompt": "Создайте репозиторий на GitHub и запушьте туда первую страницу.",

```

## Мини-игры: `content/games.json`

Один файл на весь раздел. Игра — это спринт: один вопрос = 4 варианта, 1–2 с на
объяснение, очки за серию. Типов подачи три (`kind`), механика одна.

```jsonc
{
  "games": [
    {
      "id": "selector",                  // попадёт в адрес #/game/<id> и в таблицу рекордов
      "title": "Угадай селектор",
      "tagline": "Дана разметка, нужный элемент подсвечен. ...",
      "icon": "search",                  // имя символа из спрайта templates/index.html (i-<icon>)
      "gradient": ["#6366f1", "#22d3ee"],// ровно два hex-цвета: фон карточки и акценты экрана
      "kind": "selector",                // selector | bug | flex
      "seconds": 75,                     // 30–300, длительность спринта
      "questions": [ /* не меньше 8 */ ]
    }
  ]
}
```

Общие поля вопроса: `id` (уникален в банке — по нему ругается валидатор),
`prompt`, `options` (**ровно 4**, без дублей), `answer` — индекс правильного
варианта в `options`, `explain` (не короче 30 символов). Порядок вариантов игра
перемешивает на каждом показе, поэтому `answer` — это место в исходном банке,
а не то, что видит ученик.

### `selector` — попасть селектором в помеченный элемент

`lang` всегда `html`, `code` — разметка построчно. **Каждый** элемент, в который
должен попадать верный селектор, помечен пустым атрибутом `data-target`: он
подсвечивается в живом предпросмотре и служит эталоном при проверке. В вопросах
«выбрать все подходящие» меток несколько.

```jsonc
{
  "id": "sel-01",
  "prompt": "Выбрать только «Главную»",
  "lang": "html",
  "code": [
    "<nav class=\"menu\">",
    "  <a class=\"link\" data-target>Главная</a>",
    "  <a class=\"link\">О нас</a>"
  ],
  "options": [".menu a", ".menu a:first-child", ".link .menu", ".menu > a:last-child"],
  "answer": 1,
  "explain": ":first-child берёт первого ребёнка .menu..."
}
```

Два обязательных условия, иначе вопрос ломается:

- верный вариант попадает **ровно** в помеченные элементы — ни больше, ни меньше;
- ни один неверный вариант не даёт тот же набор. Это проверяется перебором
  множеств в браузере (`querySelectorAll` на разметке вопроса), а не на глаз:
  `.toolbar :not(.spacer)` и `.gallery img:first-of-type` выглядели верными,
  но помечали ровно то же, что эталон.

Исключение — `:hover`, `::first-line`, `::first-letter` и прочие селекторы,
которые статически ни во что не попадают. Таким вопросам ставят
`"styling": true`: тогда требуется лишь, чтобы верный вариант был корректным
CSS, а остальные не помечали ничего. Из-за этого дистрактором не может служить
устаревшая однодвоеточная запись: `.lead:first-line` валиден и означает ровно
то же, что `.lead::first-line`, — то есть второй верный ответ.

### `bug` — найти настоящую причину

`lang` — `html` | `css` | `js` | `python`, `code` — битый фрагмент построчно.
Варианты — текстовые диагнозы: верным обязан быть ровно один, остальные —
правдоподобные, но ошибочные. Формулировки проверяем на двойные смыслы («дубли
вариантов» валидатор ловит, а вот «тоже правда, но не причина» — только глазами).

### `flex` — собрать показанную раскладку

Картинка-эталон рендерится живьём, поэтому кода нет — только тройка значений:

```jsonc
{
  "id": "flex-01",
  "prompt": "Три карточки в ряд, прижаты к правому краю, по вертикали — в центре",
  "items": 3,                                        // 2–4 плашки в предпросмотре
  "target": ["row", "flex-end", "center"],           // flexDirection, justifyContent, alignItems
  "options": [["row", "flex-start", "center"], ["row", "flex-end", "center"],
              ["column", "flex-end", "center"], ["row", "center", "flex-end"]],
  "answer": 1,
  "explain": "row — главная ось горизонтальна..."
}
```

Цель обязана встречаться среди `options` ровно один раз, все четыре тройки —
разными, и значения лежать в допустимых наборах (списки в начале раздела).
Эталоном считается картинка, а не `prompt`: словами раскладку описываем
приближённо, ученик сверяет с предпросмотром.

## Требования к качеству

- Минимум 2 упражнения на урок, из них хотя бы одно автоматическое (`quiz` или `code`).
- `starter` — это заготовка с `pass` / комментарием `/* тут ваш код */`, а не пустая строка.
- `hints` — 1–3 подсказки, от общей к конкретной. `solution` — рабочий эталон,
  он обязан проходить все `tests`/`checks`.
- Никаких заглушек вроде «TODO», «текст будет позже», lorem ipsum.
- Код в примерах — запускаемый, с реальными именами, без псевдокода.
- В играх — никаких «почти верных»: если два варианта дают один результат,
  переписываются оба.
