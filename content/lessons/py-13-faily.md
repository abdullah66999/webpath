## Файл открывается через open() — и его нужно закрывать

```python
f = open("notes.txt", encoding="utf-8")
text = f.read()
f.close()
```

Между `open` и `close` может произойти исключение — и файл останется незакрытым: ОС держит дескриптор, буфер не сброшен на диск, данные потеряны. Поэтому почти всегда пишут через `with`:

```python
with open("notes.txt", encoding="utf-8") as f:
    text = f.read()
# здесь файл уже закрыт — даже если внутри блока была ошибка
```

`with` (контекстный менеджер) гарантирует закрытие при любом выходе из блока. Правило простое: **открыли файл — используйте `with`**, «голый» `open()` без закрытия в реальном коде не встречается.

## Режимы открытия

Второй аргумент `open` — режим (mode):

| режим | смысл |
| --- | --- |
| `"r"` | чтение; если файла нет — `FileNotFoundError`. Режим по умолчанию |
| `"w"` | запись; **содержимое стирается сразу при открытии** |
| `"a"` | дозапись в конец, существующее содержимое сохраняется |
| `"x"` | создание нового файла; если уже есть — `FileExistsError` |
| `"b"` | суффикс для бинарных данных: `"rb"`, `"wb"` — работа с байтами |

Главная ловушка новичка — режим `"w"`. Открыли файл «просто посмотреть» в режиме `"w"` — и он уже пуст: очистка происходит в момент открытия, до всякой записи. Для чтения — только `"r"`.

Читать файл удобно построчно: `for line in f:` не загружает весь файл в память. У строк остаётся `\n` на конце — его убирают `line.rstrip()` или `line.strip()`.

## Кодировка

Текст в файле — байты, и как они превратятся в строки, решает кодировка. По умолчанию `open` берёт кодировку системы (в русской Windows это часто `cp1251`), поэтому файл, записанный в UTF-8, читается кракозябрами. Вывод один: **всегда передавайте `encoding="utf-8"` явно** — и при чтении, и при записи. UTF-8 — стандарт веба, в ней хранят JSON, конфиги и исходники.

## JSON: данные, которые понимают все

Для структурированных данных (словари, списки) текстовый формат JSON подходит лучше, чем «строки через запятую»:

```python
import json

stats = {"visits": 120, "ok": True}

with open("stats.json", "w", encoding="utf-8") as f:
    json.dump(stats, f, ensure_ascii=False, indent=2)   # словарь → файл

with open("stats.json", encoding="utf-8") as f:
    loaded = json.load(f)                              # файл → словарь
```

Запомните пары: `dump`/`load` работают **с файлом**, `dumps`/`loads` — **со строкой** (буква `s` — string). `ensure_ascii=False` разрешает кириллицу как есть, `indent=2` делает файл читаемым для человека.

## CSV: таблицы

Для табличных данных есть модуль `csv` — он сам экранирует запятые и кавычки внутри значений:

```python
import csv

with open("users.csv", "w", newline="", encoding="utf-8") as f:
    writer = csv.writer(f)
    writer.writerow(["name", "age"])
    writer.writerow(["Аня", 24])

with open("users.csv", newline="", encoding="utf-8") as f:
    for row in csv.reader(f):
        print(row)      # ['name', 'age'], затем ['Аня', '24']
```

`newline=""` при записи убирает пустые строки между записями в Windows. Все значения `csv.reader` возвращает строками — числа придётся приводить через `int()`/`float()`.

## pathlib: пути без склейки строк

Склеивать пути через `+` и `"/"` — прошлый век (в Windows разделитель `\`). Модуль `pathlib` даёт объект `Path`, который умеет всё сам:

```python
from pathlib import Path

data_dir = Path("data")
data_dir.mkdir(exist_ok=True)

report = data_dir / "report.txt"     # склейка через оператор /
report.write_text("Итоги\n", encoding="utf-8")   # запись одной строкой
print(report.read_text(encoding="utf-8"))        # чтение одной строкой

print(report.exists(), report.suffix, report.stem)   # True .txt report
for path in data_dir.glob("*.txt"):
    print(path.name)
```

Для небольших операций `write_text`/`read_text` заменяют весь ритуал с `open`. `Path(__file__).parent` в скрипте — папка самого скрипта, надёжнее относительных путей, которые считаются от текущей рабочей директории.
