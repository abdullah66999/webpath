## Приложение не слушает порт

Это звучит странно после `app.run()`, но Flask- или Django-приложение — это **WSGI-callable**: по сути функция, которая принимает запрос и возвращает ответ. Само оно не открывает сетевой порт и не принимает соединения. Этим занимается отдельная программа — WSGI-сервер.

**WSGI (Web Server Gateway Interface)** — стандартный интерфейс между веб-сервером и Python-приложением. Сервер разбирает HTTP-запрос, вызывает приложение по этому интерфейсу и отдаёт клиенту ответ. Благодаря стандарту одно и то же приложение работает под Gunicorn, uWSGI или любым другим WSGI-сервером без изменения кода.

## Почему app.run() не для прода

`app.run()` поднимает **Werkzeug** — встроенный dev-сервер для разработки. Он:

- **однопоточный** и не рассчитан на нагрузку: один медленный запрос блокирует остальных;
- **с интерактивным отладчиком**, который при ошибке позволяет выполнить произвольный код прямо на сервере;
- не защищён и не оптимизирован.

Отладчик в интернете — это дыра, через которую атакующий получает shell. В продакшне `app.run()` недопустим ни при каких условиях.

## Gunicorn перед приложением

**Gunicorn** (или uWSGI) — боевой WSGI-сервер. Он слушает порт, управляет пулом **воркеров** (worker) — отдельных процессов, каждый из которых вызывает ваше приложение, — и перезапускает упавшие.

```bash
gunicorn --workers 4 --bind 127.0.0.1:8000 app:app
```

Здесь `app:app` — это файл `app.py` и объект `app` внутри него. Четыре воркера обрабатывают запросы параллельно. Обратите внимание: Gunicorn привязан к `127.0.0.1` — наружу он не торчит, к нему обращается только nginx.

## nginx как reverse proxy

Перед Gunicorn ставят **nginx** в роли обратного прокси (reverse proxy). Клиенты стучатся на nginx, а он проксирует запросы на Gunicorn внутри машины. Зачем прослойка:

- nginx терминирует **TLS** — расшифровывает HTTPS, использует сертификаты Let's Encrypt;
- отдаёт **статику** и балансирует нагрузку между воркерами;
- гасит медленные и подозрительные соединения, защищая приложение;
- даёт единую точку входа, если за ним несколько сервисов.

## Статику отдаёт nginx, не Python

Файлы из `/static` — CSS, JavaScript, картинки — раздаёт **nginx или CDN**, а не приложение. Отдача статического файла через WSGI тратит время воркера, которое должно уйти на логику запроса. nginx же отдаёт файл с диска напрямую, быстро и без участия Python.

```text
Браузер
  │  HTTPS
  ▼
nginx:443  ── отдаёт /static, терминирует TLS
  │  proxy_pass на 127.0.0.1:8000
  ▼
Gunicorn:8000  ── 4 воркера, WSGI-сервер
  │  вызывает приложение
  ▼
Flask app  ── маршруты, шаблоны, база данных
```

## Типичные ошибки

- `app.run()` или `flask run` на боевом сервере.
- Gunicorn привязан к `0.0.0.0` и торчит в интернет без nginx и TLS.
- Статику раздаёт Flask — воркеры заняты картинками вместо запросов.
- Один воркер на весь продакшн: первый же медленный запрос тормозит всех.
