## Запрос, который читается как фраза

Основной способ достать данные из базы — запрос `SELECT`. Базовая форма:

```sql
SELECT name, price FROM products;
```

Читается почти как английский: «выбери name и price из products». После `SELECT` перечисляют столбцы, которые хотят увидеть, после `FROM` — таблицу, откуда их взять. Запись `SELECT *` означает «все столбцы». Она удобна, когда вы исследуете базу вручную, но в коде приложения перечисляйте столбцы явно.

## DISTINCT: убрать повторы

Если в столбце значения повторяются, `SELECT` вернёт их как есть. Чтобы оставить только уникальные, добавляют `DISTINCT`:

```sql
SELECT DISTINCT category FROM products;
```

Из пяти товаров двух категорий останутся две строки — по одной на категорию. `DISTINCT` работает на весь набор перечисленных столбцов: уникальными считаются комбинации значений, а не один столбец.

## LIMIT: взять только начало

`LIMIT n` ограничивает выдачу первыми `n` строками:

```sql
SELECT name, price FROM products ORDER BY price DESC LIMIT 3;
```

Три самых дорогих товара. Без сортировки «первые n» строк — понятие условное: база не гарантирует порядок, если вы его не задали.

## Псевдонимы (aliases)

Столбцу в результате можно дать другое имя через `AS`:

```sql
SELECT name AS товар, price * 0.9 AS цена_со_скидкой FROM products;
```

Псевдонимы полезны для вычисляемых столбцов (`price * 0.9` без имени выглядело бы странно) и для читаемости результата.

## Порядок выполнения не равен порядку записи

Вот главное, что снимает половину путаницы у новичка. Пишете вы `SELECT ... FROM ... WHERE ... ORDER BY`, но база выполняет запрос в другом порядке:

```
FROM → WHERE → GROUP BY → HAVING → SELECT → ORDER BY → LIMIT
```

Сначала находится таблица (`FROM`), затем отбираются строки (`WHERE`), потом считается то, что перечислено в `SELECT`, и только в конце сортируется и обрезается результат. Отсюда следствие: в `WHERE` нельзя использовать псевдоним из `SELECT` — на момент фильтрации его ещё не существует. А в `ORDER BY` можно — сортировка идёт уже после `SELECT`.

## Типовая ошибка

`SELECT *` в коде приложения. Кажется удобным: «возьму всё, а там разберусь». Но так вы тянете из базы лишние столбцы (трафик и память), а добавление нового столбца в таблицу молча ломает код, который ожидал фиксированный набор. Перечисляйте только то, что реально используете:

```sql
-- плохо
SELECT * FROM users WHERE id = 42;
-- хорошо
SELECT id, name, email FROM users WHERE id = 42;
```

Вторая частая ошибка — отладочный `SELECT * FROM big_table` без `LIMIT` на таблице в миллион строк: клиент виснет, пытаясь выкачать всё.
