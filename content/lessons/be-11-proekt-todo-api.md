## Что вы строите

Итоговый проект этапа — API для списка задач с полным набором операций CRUD (Create, Read, Update, Delete). Данные пока живут в памяти процесса. Это сознательное ограничение, и к концу урока станет понятно, почему следующее — базы данных.

Проект собирается из всего, что вы прошли: маршруты с конвертерами, чтение `request`, валидация, `jsonify` с корректными статусами, единый формат ошибки, обработчики исключений, blueprint'ы и фабрика приложения.

## Структура

```text
tasks-api/
├─ app/
│  ├─ __init__.py       # create_app
│  ├─ config.py         # BaseConfig, DevelopmentConfig, TestingConfig
│  ├─ errors.py         # errorhandler для 404, HTTPException, Exception
│  └─ tasks/
│     ├─ __init__.py
│     ├─ routes.py      # blueprint: разбор запроса и ответ
│     ├─ service.py     # валидация, создание, обновление, удаление
│     └─ storage.py     # словарь в памяти и next_id
├─ tests/
├─ .env.example
└─ pyproject.toml
```

Слои зависят друг от друга только сверху вниз: `routes` → `service` → `storage`. В `service` нет ни `request`, ни `jsonify` — иначе его нельзя протестировать без сервера.

## Формат данных

```json
{
  "id": 1,
  "title": "Купить молоко",
  "done": false,
  "created_at": "2026-02-11T18:30:00Z",
  "url": "/api/v1/tasks/1"
}
```

`created_at` — строка в формате ISO 8601 в UTC. `url` собирайте через `url_for("tasks.task_detail", task_id=task["id"])`.

## Эндпоинты и коды ответов

- `GET /api/v1/tasks` → **200** с телом `{"items": [...], "total": N, "limit": L, "offset": O}`. Пустой список — это **200** и `"items": []`, не 404. Поддерживает `?done=true`, `?q=подстрока`, `?limit` (1–100, по умолчанию 20), `?offset` (по умолчанию 0). Значение вне диапазона, например `?limit=1000`, → **400**.
- `GET /api/v1/tasks/<int:task_id>` → **200** с объектом; **404**, если задачи нет.
- `POST /api/v1/tasks` → **201** с объектом и заголовком `Location`; **400**, если тело не JSON; **422** с `"field": "title"`, если заголовок пустой или длиннее 200 символов.
- `PUT /api/v1/tasks/<int:task_id>` → полная замена: **200** с новым объектом; **404**, если задачи нет; **400** на не-JSON; **422**, если `title` отсутствует или невалиден.
- `PATCH /api/v1/tasks/<int:task_id>` → частичное обновление тех же полей; те же коды, но `title` не обязателен.
- `DELETE /api/v1/tasks/<int:task_id>` → **204** без тела; **404**, если задачи уже нет.

## Валидация

- `title` — обязательная строка, после `strip()` от 1 до 200 символов.
- `done` — необязательное, приводится к `bool`. Если прислали не логическое значение и не `true`/`false` — **422** с `"field": "done"`.
- Неизвестные поля игнорируются молча: клиент не должен иметь возможность подменить `id` или `created_at`.
- Все значения из запроса проверяются на тип до того, как попадут в `service`.

Единая форма ошибки:

```json
{
  "error": { "status": 422, "message": "заголовок не может быть пустым", "field": "title" }
}
```

## Хранение в памяти — и почему это тупик

```python
# app/tasks/storage.py
TASKS = {
    1: {"id": 1, "title": "Купить молоко", "done": False,
        "created_at": "2026-02-11T18:30:00Z"},
}


def next_id(tasks):
    ids = [task["id"] for task in tasks if "id" in task]
    return max(ids) + 1 if ids else 1
```

Перезапуск процесса стирает всё. `app.run(debug=True)` перезапускает сервер при каждом сохранении файла — вы будете терять данные постоянно. Добавьте второй процесс gunicorn, и у каждого окажется своя копия словаря. Добавьте поиск по подстроке — и он перебирает весь список в памяти на каждый запрос.

Промежуточный вариант — сбрасывать словарь в JSON-файл. Он решает проблему перезапуска, но не решает ничего остального: две одновременные записи в файл испортят его, а индексов и связей между таблицами в JSON не бывает.

Именно это вы исправите на следующем этапе: SQLite, SQL-запросы и SQLAlchemy. Заодно разберёте параметризованные запросы — единственный правильный способ подставлять значения из `request` в SQL.

## Чек-лист готовности

Пройдитесь по нему перед тем, как считать проект сделанным. Все пункты проверяются через `curl -i` или вкладку Network — глазами, без магии:

- `flask --app app run --debug` стартует без ошибок и печатает `Running on http://127.0.0.1:5000`.
- `GET /api/v1/tasks` отдаёт `200` и объект с ключами `items`, `total`, `limit`, `offset`; при пустом хранилище `items` — пустой массив.
- Фильтры работают: `?done=false` оставляет только открытые, `?q=молоко` ищет по подстроке, `?limit=1000` возвращает `400`.
- `POST` с валидным `title` возвращает `201`, заголовок `Location` и объект с `id` и `created_at`; с пустым `title` — `422` и `"field": "title"`; с телом не-JSON — `400`, а не `500`.
- `GET /api/v1/tasks/999` отдаёт `404` в том же JSON-формате ошибки, что и остальные неудачи.
- `PUT` полностью заменяет запись и требует `title`, `PATCH` меняет только переданные поля и игнорирует попытку прислать `id`; оба отвечают `404` на несуществующую задачу.
- `DELETE` возвращает `204` с пустым телом, повторный `DELETE` того же `id` — `404`.
- Запрос к несуществующему адресу отдаёт JSON-ошибку, а не HTML-страницу Werkzeug: обработчики из `errors.py` зарегистрированы.
