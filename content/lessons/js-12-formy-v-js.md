## Зачем форме JavaScript

Браузер умеет проверять формы сам: атрибуты `required`, `type="email"`, `minlength` и `pattern` дают встроенную валидацию (validation). Но у неё два недостатка — сообщения нельзя переписать под ваш тон, а проверить поля до отправки не получается. Поэтому живая форма устроена так: браузерная проверка остаётся страховкой, а сценарий ведёт JavaScript.

Если сообщениями хотите управлять вы, форму помечают атрибутом `novalidate`:

```html
<form id="signup" novalidate>
```

## Событие submit

Работа начинается с события `submit`. Оно срабатывает и при клике по кнопке `type="submit"`, и при нажатии Enter в текстовом поле — поэтому обработчик вешают на форму, а не на кнопку.

```js
const form = document.querySelector('#signup');

form.addEventListener('submit', function (event) {
  event.preventDefault();   // без этой строки страница перезагрузится
  send(form);
});
```

`event.preventDefault()` — почти всегда первая строка. Без неё браузер выполнит действие по умолчанию: уйдёт запрос, страница перезагрузится, а ваш код и всё состояние исчезнут. Симптом знакомый: сообщение об ошибке мелькает на долю секунды и пропадает.

Отправлять форму из кода надо через `form.requestSubmit()`, а не `form.submit()`. Второй способ не вызывает событие `submit` и не запускает проверку — ваш обработчик просто не выполнится.

## Чтение значений

К полям можно обращаться по имени через коллекцию `elements`:

```js
const email = form.elements.email;         // поле с name="email"
const value = email.value.trim();
```

Когда полей много, их удобнее собрать разом через `FormData`:

```js
const data = new FormData(form);
const payload = Object.fromEntries(data);  // { name: 'Аня', city: 'Тверь' }
```

В `FormData` попадают только заполненные элементы: неотмеченный чекбокс отсутствует вовсе, а отмеченный без атрибута `value` даёт `on`. `trim()` обязателен — строка из одних пробелов иначе пройдёт проверку на «не пусто».

## Валидация и текст ошибки

Проверяйте поля независимо и возвращайте набор ошибок, а не одну:

```js
function validate(form) {
  const errors = {};
  const email = form.elements.email.value.trim();

  if (!email) errors.email = 'Укажите почту';
  else if (!email.includes('@')) errors.email = 'В почте должен быть символ @';

  return errors;
}
```

Пустой объект означает «всё в порядке». Такую функцию легко расширять, в отличие от длинной цепочки `if`, где сообщение живёт вперемешку с логикой отправки.

## Состояние кнопки

Пока запрос идёт, кнопку блокируют. Иначе пользователь нажмёт её ещё три раза, и в базу уедут четыре одинаковых заказа:

```js
button.disabled = true;
button.textContent = 'Отправляем…';

try {
  await send(data);
  button.textContent = 'Готово';
} catch (error) {
  button.disabled = false;                 // обязательно возвращаем
  button.textContent = 'Попробовать снова';
}
```

## Доступность ошибок

Сообщение должно быть связано с полем, иначе скринридер его не прочитает:

```html
<label for="email">Почта</label>
<input id="email" name="email" type="email" aria-describedby="email-error">
<p id="email-error" class="error" role="alert"></p>
```

```js
input.setAttribute('aria-invalid', 'true');
document.querySelector('#email-error').textContent = 'Укажите почту';
input.focus();
```

`aria-invalid` сообщает, что значение неверное, `aria-describedby` связывает поле с сообщением, `role="alert"` заставляет скринридер прочитать текст сразу. После исправления `aria-invalid` снимают, а сообщение очищают. Фокус возвращают на проблемное поле — мышью человек найдёт его сам, с клавиатуры это мучительно.

И правило, которое уже звучало на первом уроке: клиентская валидация — удобство, а не защита. Запрос можно отправить вручную, вообще без страницы, поэтому сервер проверяет те же поля заново.

## Типичные ошибки

- Забыли `preventDefault()` — страница перезагружается.
- Ошибка выводится через `alert` или в `placeholder`: её не увидит скринридер, и она исчезает вместе с фокусом.
- Кнопку заблокировали и не разблокировали после ошибки — форма умерла навсегда.
- Проверяют `value` без `trim()`.
- Одна общая ошибка на всю форму вместо сообщения у конкретного поля.
