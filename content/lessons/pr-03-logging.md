## print в продакшне не работает

`print` удобен, пока вы учитесь. В реальном сервисе он бесполезен: уходит в stdout без уровня и времени, а агрегатор логов хостинга не поймёт, что важно, а что нет. Вы не сможете отфильтровать «только ошибки» и не увидите, когда случилось событие. Для этого есть модуль **logging**.

## Уровни важности

Каждому событию задают уровень (level). Пять стандартных, по возрастанию серьёзности:

- **DEBUG** — детали для разработки: промежуточные значения, шаги алгоритма.
- **INFO** — нормальные события: сервис стартовал, заказ создан, пользователь вошёл.
- **WARNING** — неожиданно, но не фатально: повторная попытка, устаревший метод, запасной путь.
- **ERROR** — операция провалилась: не удалось сохранить в базу, внешний API ответил ошибкой.
- **CRITICAL** — приложение не может продолжать работу.

Уровень настраивается: `level=logging.INFO` означает «INFO и выше». Всё, что ниже (DEBUG), отсекается — поэтому в проде DEBUG-сообщений не видно, а на стенде отладки их включают.

## Настройка и формат

```python
import logging

logging.basicConfig(
    level=logging.INFO,
    format="%(asctime)s %(levelname)s %(name)s: %(message)s",
)
logger = logging.getLogger("orders")

logger.info("заказ 42 создан")
logger.error("не удалось списать оплату по заказу 42")
```

Формат с `%(asctime)s` и `%(levelname)s` даёт время и уровень в каждой строке — ровно то, чего нет у `print`.

## Исключения — через logger.exception()

Внутри блока `except` вызывайте `logger.exception(...)`: он запишет сообщение **и добавит полный трейсбек**. Это главный инструмент диагностики — по стеку видно, где именно упало.

```python
try:
    charge(order_id)
except Exception:
    logger.exception("сбой оплаты заказа %s", order_id)
    raise
```

`logger.error("...")` без трейсбека оставит вас гадать, что случилось. Если нужно приложить стек вручную, есть `logger.error(..., exc_info=True)`, но `exception()` короче.

## Структурированные логи

Лог в формате JSON (одна строка — одна запись с полями) удобно разбирать машиной и искать по конкретным ключам: `event`, `user_id`, `order_id`. Так из потока строк получается данные, по которым строят графики и алерты.

## Что нельзя логировать никогда

В логи не попадают **пароли, токены, полные номера карт и персональные данные**. Это не только здравый смысл, но и требование законодательства о персональных данных (GDPR, 152-ФЗ): лог-файл с секретами — такая же утечка. Если значение нужно для идентификации, логируйте маскированный хвост (`****3456`), а не всё целиком.

## Типичные ошибки

- `print` вместо logging — в сервисе его не разобрать.
- `logger.error(e)` в `except` без трейсбека: нужен `logger.exception`.
- Уровень DEBUG в проде — тонны мусора и просадка производительности.
- Секрет или полный номер карты в строке лога.
