## Минимальный набор

До конца курса вы почти каждый день работаете с четырьмя программами: редактором кода, терминалом, браузером и Git. У каждой своя роль, и заменить друг друга они не могут.

## Редактор кода

Место, где вы пишете код. Не «Блокнот» и не Word: редактор кода (code editor) подсвечивает синтаксис, подсказывает имена, подчёркивает ошибки ещё до запуска и содержит встроенный терминал. Стандарт индустрии — бесплатный VS Code, работает на Windows, macOS и Linux. Альтернативы: Sublime Text и Zed — лёгкие редакторы того же класса; PyCharm — уже IDE (integrated development environment), комбайн «всё в одном», потяжелее.

Не выбирайте неделю: подойдёт любой современный редактор, в курсе ориентируемся на VS Code.

Привычка, которую нужно завести сразу: **проект открывается как папка** («Файл → Открыть папку»), а не как один файл. Тогда поиск, интеграция с Git и встроенный терминал видят весь проект; иначе редактор знает только про один файл и ничего — про его соседей.

## Терминал

Окно, в котором вы отдаёте компьютеру команды текстом: запускаете программы, управляете файлами, работаете с Git. Без него не обойтись по двум причинам. Во-первых, на серверах графического интерфейса нет вовсе — только консоль, и ваш будущий бэкенд вы будете запускать именно так. Во-вторых, десятки ежедневных операций командой выполняются быстрее, чем кликами.

В Windows соседствуют три оболочки (shell) — и тут новички путаются:

- **cmd** — старая оболочка Windows, команды у неё свои: `dir`, `copy`, `del`.
- **PowerShell** — современная оболочка Windows, мощнее и частично понимает unix-команды: `ls` там работает.
- **Git Bash** — unix-оболочка, которая ставится вместе с Git. Внутри неё в Windows работают `ls`, `cat`, `touch`, `grep` — всё, чем пользуется курс.

На macOS и Linux оболочка — bash или zsh, unix-команды там родные. Команды в уроках будем давать парами, чтобы вы могли работать в любой системе.

## Браузер

У браузера две роли. Первая — показывать, что вы собрали. Вторая — диагностировать: в него встроены инструменты разработчика (DevTools) — инспектор разметки, консоль и панель сети. Следующий урок целиком про них. Держите два-три браузера — например, Chrome и Firefox: страницу в конце курса придётся проверять на кроссбраузерность.

## Git

Система контроля версий: запоминает каждое изменение файлов, позволяет откатиться к любой версии, работать в параллельных ветках и в команде, не перезаписывая друг друга. Git ставится один раз; установщик Git for Windows заодно даёт вам Git Bash. Командам Git посвящены два последних урока модуля — сейчас достаточно просто установить его.

## Как инструменты связаны

Цикл работы один и тот же всю дорогу: написали код в редакторе — запустили в терминале — посмотрели результат в браузере — зафиксировали изменение коммитом Git — отправили на сервер через push. Когда что-то ломается, диагностируете в том же порядке: браузер (DevTools) — терминал (вывод ошибок) — редактор (код).

## Типичные ошибки

- Открыли один файл вместо папки проекта — половина возможностей редактора не работает.
- Набрали unix-команду в cmd и получили «не является внутренней или внешней командой». Unix-команды в Windows живут в Git Bash и частично в PowerShell.
- Неделю выбирают и ставят инструменты, не написав ни строчки кода. Установите VS Code и Git за пятнадцать минут и начинайте работать — остальное нарастёт по ходу.
