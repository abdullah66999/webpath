## Из чего состоит запрос

В прошлом уроке вы видели обмен браузера и сервера снаружи. Теперь заглянем внутрь сообщений — именно с этой структурой вы будете работать каждый день, когда начнёте писать бэкенд.

Запрос по HTTP (HyperText Transfer Protocol) состоит из трёх частей: стартовая строка, заголовки, тело. Стартовая строка — метод, путь и версия протокола: `GET /page HTTP/1.1`. Дальше идут заголовки (headers), по одному в строке, в формате `Ключ: Значение` — служебная информация: формат данных, кодировка, кеширование, авторизация. Пустая строка — и тело (body): сама полезная нагрузка, HTML-страница, JSON или картинка. Тело необязательно: у GET-запроса его обычно нет.

Ответ устроен так же, только в стартовой строке вместо метода и пути — код состояния: `HTTP/1.1 200 OK`.

## Методы: что хотят от сервера

Метод — первое слово запроса. Пятёрка основных закрывает почти всё:

- **GET** — прочитать. Открытие страницы, скачивание картинки. Ничего на сервере не меняет.
- **POST** — прислать данные и создать. Отправка формы, регистрация, новый комментарий. Данные — в теле.
- **PUT** — заменить ресурс целиком: прислать его новую полную версию.
- **PATCH** — обновить частично: поменять только присланные поля.
- **DELETE** — удалить.

Один и тот же адрес `/users/42` допускает все пять методов: прочитать профиль, заменить его, переименовать, удалить. Действие выбирает метод, а не адрес — на этой договорённости держится любой REST API, который вы построите сами на этапе бэкенда.

Сам браузер отправляет только GET и POST (из форм). Остальные методы используют JavaScript-код и программы вроде curl.

## Коды состояния: три цифры диагноза

Коды сгруппированы по первой цифре:

- **2xx — успех**: 200 OK, 201 Created (ресурс создан), 204 No Content (сделано, возвращать нечего).
- **3xx — перенаправления**: 301 Moved Permanently — адрес переехал навсегда; 304 Not Modified — файл не изменился, берите из кеша.
- **4xx — ошибка клиента**: 400 Bad Request (в запросе бессмыслица), 401 Unauthorized (не предъявили авторизацию), 403 Forbidden (предъявили, но доступ запрещён), 404 Not Found (по этому адресу ничего нет).
- **5xx — ошибка сервера**: 500 Internal Server Error (код сервера упал), 502 Bad Gateway, 503 Service Unavailable.

Водораздел такой: **4xx — виноват тот, кто спрашивает, 5xx — тот, кто отвечает**. 404 не означает «сайт сломался»: сервер жив и корректно ответил, просто документа по такому адресу у него нет. Если бы сервер действительно лежал, HTTP-ответа не было бы вовсе — браузер показал бы ошибку соединения.

## Четыре заголовка, которые нужно знать в лицо

Заголовков десятки, но для начала хватает этих:

- `Content-Type` — что лежит в теле: `text/html; charset=utf-8`, `application/json`. Без него получателю придётся угадывать формат.
- `User-Agent` — кто спрашивает: браузер и версия, операционная система.
- `Authorization` — удостоверение личности, например `Bearer <токен>` после входа.
- `Cache-Control` — сколько времени ответ можно хранить и не спрашивать сервер заново.

## Типичные ошибки

Клиент отправляет в теле POST JSON, но забывает заголовок `Content-Type: application/json` — сервер разбирает тело как данные формы и отвечает 400. Симметричная ошибка с другой стороны: сервер присылает JSON с заголовком `text/html`, и браузер показывает «кашу» вместо данных.

Не путайте 401 и 403. 401 — сервер не понял, кто вы: токена нет или он истёк. 403 — сервер отлично понял, кто вы, но доступ запрещён. Логиниться заново при 403 бесполезно.
