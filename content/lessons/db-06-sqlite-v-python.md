## sqlite3 уже встроен в Python

Модуль `sqlite3` входит в стандартную библиотеку Python — ничего устанавливать не нужно. SQLite хранит всю базу в одном файле, идеален для обучения, локальной разработки и небольших приложений. Подключение:

```python
import sqlite3

conn = sqlite3.connect("shop.db")   # создаст файл, если его нет
cursor = conn.cursor()
```

`conn` — соединение с базой, `cursor` — объект, через который выполняют запросы и читают результат.

## Выполняем запросы

```python
cursor.execute("CREATE TABLE IF NOT EXISTS users (id INTEGER PRIMARY KEY, name TEXT)")
cursor.execute("INSERT INTO users (name) VALUES (?)", ("Аня",))
conn.commit()                        # фиксируем изменения

cursor.execute("SELECT id, name FROM users")
rows = cursor.fetchall()             # список кортежей
for row in rows:
    print(row)                        # (1, 'Аня')
```

`execute` выполняет один запрос, `fetchall` забирает все строки результата (есть ещё `fetchone` — одна строка и `fetchmany(n)`). Каждый ряд — кортеж значений в порядке перечисленных столбцов.

## Параметризованные запросы — единственный верный путь

Значения **никогда** не подставляют в строку запроса склейкой, f-строкой или `%`. Для этого есть плейсхолдер `?` и отдельный кортеж параметров:

```python
cursor.execute("SELECT * FROM users WHERE name = ?", (name,))
```

Заметили запятую в `(name,)`? Это кортеж из одного элемента — без запятой были бы просто скобки, и sqlite3 выдал бы ошибку. Параметров может быть несколько: `WHERE a = ? AND b = ?`, `("x", 42)`.

## SQL-инъекция: как это работает

Склейка выглядит невинно, пока в поле имени не придёт `' OR '1'='1`:

```python
# УЯЗВИМО — не пишите так никогда
query = "SELECT * FROM users WHERE name = '" + name + "'"
```

Если `name` равен `' OR '1'='1`, строка превращается в:

```sql
SELECT * FROM users WHERE name = '' OR '1'='1'
```

Условие `'1'='1'` всегда истинно — запрос отдаёт **все** строки таблицы. Так обходят вход без пароля и выкачивают данные. Подставить можно и хуже: `'; DROP TABLE users; --` удалит таблицу.

Параметризованный запрос так взломать нельзя: драйвер передаёт значение **как данные**, отдельно от SQL. Даже строка `' OR '1'='1` станет просто именем, которое ищется буквально, — совпадений не найдётся. Это главный урок безопасности на всём этапе.

## Транзакции: commit и rollback

Изменения (`INSERT`, `UPDATE`, `DELETE`) не видны другим и не сохраняются в файл, пока вы не вызовете `conn.commit()`. Забыли commit — данные потеряются при закрытии соединения. Если в середине нескольких операций произошла ошибка, `conn.rollback()` откатывает всё до последнего коммита.

Удобнее всего использовать менеджер контекста — он сам сделает commit при успехе и rollback при исключении:

```python
with conn:                       # авто-commit / rollback
    conn.execute("INSERT INTO users (name) VALUES (?)", ("Борис",))
    conn.execute("UPDATE users SET name = ? WHERE id = ?", ("Анна", 1))
```

В конце не забудьте `conn.close()`.

## Типовая ошибка

Забытый `conn.commit()` после вставки: в отладчике строка как будто есть, а при следующем запуске программы её нет. И второе — `SELECT *` в коде: тянете лишние столбцы, а порядок значений в кортеже ломается при изменении таблицы. Перечисляйте столбцы явно.
