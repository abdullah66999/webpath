## Агрегатные функции: сворачиваем строки в число

Агрегатные функции превращают набор строк в одно значение. Пять основных:

```sql
SELECT COUNT(*), SUM(amount), AVG(amount), MIN(amount), MAX(amount) FROM sales;
```

`COUNT` считает строки, `SUM` складывает, `AVG` усредняет, `MIN` и `MAX` находят крайние значения. Все они, кроме `COUNT(*)`, игнорируют NULL.

## COUNT(*) против COUNT(столбец)

Классическая ловушка. `COUNT(*)` считает **все** строки, включая те, где есть NULL. `COUNT(amount)` считает только строки, где `amount` не NULL:

```sql
SELECT COUNT(*), COUNT(amount) FROM sales;
```

Если из пяти строк у одной amount пустой, результат будет `5` и `4`. Разница молчаливая и легко ломает отчёт: вы думаете, что посчитали все заказы, а часть с пустой суммой просто не попала в `COUNT(amount)`.

## GROUP BY: агрегат по группам

Без `GROUP BY` агрегат сворачивает всю таблицу в одну строку. Чтобы получить сумму по каждому городу, строки сначала группируют:

```sql
SELECT city, SUM(amount) FROM sales GROUP BY city;
```

`GROUP BY city` разбивает строки на группы по значению city, затем `SUM` считается внутри каждой. В `SELECT` можно перечислять только столбцы из `GROUP BY` и агрегаты — иначе СУБД не поймёт, какое именно значение показать.

## HAVING против WHERE

`WHERE` фильтрует строки **до** группировки, `HAVING` — группы **после** агрегации. Ошибка новичка — попытаться фильтровать агрегат через `WHERE`:

```sql
-- НЕ РАБОТАЕТ: WHERE выполняется до GROUP BY и не знает про SUM
SELECT city, SUM(amount) FROM sales
WHERE SUM(amount) > 200 GROUP BY city;

-- правильно: HAVING фильтрует уже посчитанные группы
SELECT city, SUM(amount) FROM sales
GROUP BY city HAVING SUM(amount) > 200;
```

Запомните порядок: `FROM → WHERE → GROUP BY → HAVING → SELECT`. Строки отсеиваются `WHERE`, затем оставшиеся группируются, затем `HAVING` отсеивает целые группы по их агрегату.

## Деньги — не float

Хранить сумму во `float` (или `REAL`) нельзя: двоичная дробь не представляет 0.1 точно, и `0.1 + 0.2` даёт `0.30000000000000004`. На тысячах операций расхождение накопится в реальную недостачу. Деньги хранят либо целым числом минимальных единиц (копейки, центы), либо типом `NUMERIC`/`DECIMAL`. Агрегат `SUM` по копеечным целым всегда точен.

## Оконные функции — вкратце

Иногда агрегат нужен, но сворачивать строки в одну группу не хочется: например, показать сумму заказов клиента рядом с каждым его заказом. Это делают оконные функции (window functions):

```sql
SELECT user_id, amount,
       SUM(amount) OVER (PARTITION BY user_id) AS total_by_user
FROM orders;
```

`OVER (PARTITION BY ...)` вычисляет агрегат «поверх» строк, не схлопывая их. Подробно их разбирают позже — сейчас достаточно знать, что такая возможность есть и она мощнее `GROUP BY`.

## Типовая ошибка

Агрегат в `WHERE` вместо `HAVING` — запрос падает с ошибкой или (что хуже) молча считает не то. Правило: всё, что про отдельные строки, — в `WHERE`; всё, что про группы и их агрегаты, — в `HAVING`.
