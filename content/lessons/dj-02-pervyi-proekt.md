## Два инструмента: django-admin и manage.py

Проект создаётся утилитой `django-admin`, а живёт через `manage.py`. Разница простая: `django-admin` ничего не знает о вашем проекте, поэтому годится только чтобы его создать. `manage.py` появляется внутри проекта и читает его `settings.py`, поэтому все остальные команды — запуск сервера, миграции, тесты — вызывают через неё.

```bash
django-admin startproject config .   # каркас проекта, точка — «в текущую папку»
python manage.py startapp posts       # приложение внутри проекта
python manage.py runserver            # dev-сервер
```

## Проект и приложение

**Проект** (project) — это настройки и конфигурация: `settings.py`, корневой `urls.py`, точка входа `manage.py`. **Приложение** (app) — кусок функциональности со своими моделями, view и шаблонами: `posts`, `blog`, `shop`. В одном проекте может быть много приложений. Такое разделение позволяет переиспользовать приложение между проектами и держать код разложенным по ответственности.

После `startapp posts` вы получаете файлы: `models.py` (модели ORM), `views.py` (обработчики), `admin.py` (регистрация в админке), `apps.py` (конфиг) и папку `migrations/`.

## INSTALLED_APPS — реестр подключённого

Django видит только те приложения, которые перечислены в `INSTALLED_APPS`. Создали `posts` — добавьте строку в список, иначе модели не загрузятся, миграции не создадутся, а админка не покажет приложение.

```python
INSTALLED_APPS = [
    "django.contrib.admin",
    "django.contrib.auth",
    # ... остальные встроенные ...
    "posts",   # без этой строки приложения как будто нет
]
```

Встроенные `django.contrib.*` дают ту самую «батарейку»: `auth` — пользователей и пароли, `admin` — панель, `sessions` — сессии.

## runserver и DEBUG

`runserver` поднимает dev-сервер с автоперезагрузкой при изменении кода. Он только для разработки: однопоточный, без защит, для продакшна не годится — там нужен gunicorn или uWSGI за nginx.

Флаг `DEBUG` в `settings.py` управляет страницами ошибок. При `DEBUG = True` любая ошибка показывает посетителю трейсбек с исходниками, значениями переменных и частью настроек.

> `DEBUG = True` в проде — это не «не рекомендуется», а **нельзя**: страница ошибки выдаёт секретный ключ, пути и переменные окружения первому встречному. В бою `DEBUG = False`, а ошибки пишутся в лог.

## Типовая ошибка

Создали приложение, но забыли добавить его в `INSTALLED_APPS` — и час ищут, почему `makemigrations` отвечает «No changes detected», а модель не сохраняется. Второй промах — `startproject config` без точки в конце: проект уезжает во вложенную папку `config/config`, и `manage.py` оказывается не там, где вы его ждёте. Точка ставит каркас прямо в текущую директорию.
