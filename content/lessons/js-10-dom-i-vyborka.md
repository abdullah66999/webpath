## Что такое DOM

Браузер разбирает HTML и строит из него дерево объектов — **DOM** (Document Object Model). Тег становится элементом, текст внутри него — текстовым узлом, и всё это доступно из JavaScript через объект `document`. Скрипт умеет не только читать дерево, но и менять его на ходу: страница перестаёт быть статичной картинкой.

## Выбор элементов

Два главных метода — `querySelector` и `querySelectorAll`. Оба принимают обычный CSS-селектор.

```js
const title = document.querySelector('#title');   // первый подходящий элемент
const rows = document.querySelectorAll('.row');   // все подходящие
```

`querySelector` возвращает **первый** найденный элемент, а если ничего не нашёл — `null`, не `undefined` и не пустой массив. Поэтому перед обращением к свойству результат полезно проверять: `if (!title) return;`. Иначе получите «Cannot set properties of null».

`querySelectorAll` отдаёт статический список `NodeList`: он не меняется, когда меняется DOM. По нему можно ходить через `forEach` или обычный цикл. Старые методы вроде `getElementsByClassName` возвращают «живую» коллекцию — она обновляется сама, и именно из-за этого ломается цикл с удалением элементов. В новом коде их почти не используют.

## Навигация по дереву

Нашли узел — из него можно пойти дальше, не перебирая весь документ:

```js
const item = document.querySelector('.item');
item.parentElement;        // родитель
item.children;             // дочерние элементы
item.nextElementSibling;   // следующий сосед
item.closest('.card');     // ближайший подходящий предок, включая сам элемент
```

`closest` — самый полезный из них. Он спасает, когда в списке десятки кнопок и нужно понять, к какому именно пункту относится нажатие: `button.closest('li')` поднимается вверх по дереву и возвращает нужный пункт.

## textContent против innerHTML

Оба свойства меняют содержимое элемента, но делают это принципиально по-разному.

- `textContent` вставляет **текст как есть**. Всё, что похоже на теги, останется текстом.
- `innerHTML` разбирает строку как **HTML**. Теги становятся настоящими элементами.

```js
const raw = '<img src=x onerror=steal(document.cookie)>';
el.textContent = raw;   // на экране появится сам код
el.innerHTML = raw;     // браузер выполнит чужой скрипт
```

Отсюда правило, которое стоит запомнить навсегда: **данные от пользователя или с сервера вставляйте только через `textContent`**. Чужая строка в `innerHTML` — это XSS (cross-site scripting): злоумышленник подставляет тег со скриптом, скрипт выполняется на вашей странице и от имени вашего посетителя крадёт куки или отправляет запросы. `innerHTML` уместен, когда строку целиком написали вы сами.

## Создание и удаление узлов

```js
const item = document.createElement('li');
item.className = 'task';
item.textContent = 'Купить хлеб';

list.append(item);   // в конец
list.prepend(item);  // в начало
item.remove();       // удалить себя
```

Если узлов много, собирайте их в `DocumentFragment` и вставляйте в DOM один раз. Каждая вставка может запустить перерасчёт геометрии страницы, и сто отдельных `append` заметно медленнее одного.

## Типичные ошибки

- Обращение к элементу, которого нет: `null.textContent` падает с ошибкой и обрывает весь скрипт ниже.
- Скрипт в `<head>` выше разметки — элементов в DOM ещё не существует. Ставьте `<script>` в конец `<body>` или добавляйте атрибут `defer`.
- `innerHTML += 'новый кусок'` пересоздаёт всё содержимое элемента: теряются слушатели событий и введённый в полях текст.
- Цикл по «живой» коллекции с одновременным удалением пропускает каждый второй элемент.
