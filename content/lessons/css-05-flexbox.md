## Зачем нужен Flexbox

До 2015 года раскладку собирали из `float`, таблиц и отрицательных отступов. Вертикальное центрирование было отдельной дисциплиной с десятком рецептов. Flexbox закрыл эту проблему: он создан ровно для того, чтобы распределять элементы вдоль **одной оси** и управлять свободным местом.

Одноосность — ключевое ограничение. Если нужно выстроить сетку сразу по строкам и столбцам, это Grid (следующий урок). Если ряд кнопок, шапка, карточка, список пунктов — это Flexbox.

## Контейнер и элементы

Flexbox всегда работает в паре: есть **flex-контейнер** и его **прямые потомки**. Свойства применяются либо к контейнеру, либо к потомкам, и путать их — самая частая ошибка новичка.

```css
.nav { display: flex; }   /* контейнер */
.nav > a { flex: 1; }     /* потомки */
```

`display: flex` меняет поведение только прямых детей. Внуки остаются обычными блоками, пока вы не сделаете их родителя контейнером тоже.

## Две оси

У flex-контейнера есть **главная ось** (main axis) и **поперечная** (cross axis), и они всегда перпендикулярны.

`flex-direction` задаёт главную ось:

- `row` — горизонталь, слева направо. Значение по умолчанию.
- `column` — вертикаль, сверху вниз.
- `row-reverse` и `column-reverse` — то же, но в обратном порядке.

Запомните правило, и половина путаницы исчезнет: **`justify-content` работает вдоль главной оси, `align-items` — вдоль поперечной**. Если направление `row`, то `justify-content` двигает элементы влево-вправо, а `align-items` — вверх-вниз. Поменяйте направление на `column` — и они поменяются ролями.

## Распределение места

`justify-content` решает, куда денется свободное место на главной оси:

| значение | поведение |
| --- | --- |
| `flex-start` | всё прижато к началу (по умолчанию) |
| `center` | всё по центру |
| `flex-end` | всё прижато к концу |
| `space-between` | первый и последний у краёв, остальные равномерно |
| `space-around` | равные отступы вокруг каждого |
| `space-evenly` | равные промежутки везде, включая края |

`align-items` делает то же для поперечной оси: `stretch` (растянуть, по умолчанию), `center`, `flex-start`, `flex-end`, `baseline`.

Классическое центрирование блока по обеим осям — две строки:

```css
.hero {
  display: flex;
  justify-content: center;
  align-items: center;
  min-height: 100vh;
}
```

## Отступы и рост

`gap` задаёт расстояние между элементами. Это заметно чище, чем `margin` у каждого потомка: не появляются лишние отступы по краям и не нужно думать о схлопывании.

```css
.toolbar {
  display: flex;
  gap: 10px;
}
```

Свойства потомка управляют его размером:

- `flex-grow` — какую долю свободного места забрать. `0` значит «не растягиваться».
- `flex-shrink` — можно ли сжиматься, когда места не хватает.
- `flex-basis` — стартовый размер до распределения места.

Сокращение `flex: 1` равно `flex-grow: 1; flex-shrink: 1; flex-basis: 0%` — «займи всё, что свободно». Именно так делают колонки одинаковой ширины и прижимают один элемент к правому краю: ему задают `flex: 1`, и он выталкивает соседей.

## Порядок и перенос

`flex-wrap: wrap` разрешает элементам переноситься на следующую строку, когда они не помещаются. Без него они будут сжиматься до нечитаемого состояния. Для панелей фильтров и тегов почти всегда нужен `wrap`.

`order` меняет визуальный порядок, не трогая HTML. Пользуйтесь осторожно: скринридеры и переход по Tab следуют порядку в разметке, а не визуальному — расхождение сбивает людей с клавиатурной навигацией.

## Частые ошибки

- Задали `justify-content` потомку вместо контейнера — ничего не произошло.
- Ждёте, что `align-items: center` сработает без высоты: поперечная ось схлопнулась, центрировать нечего. Нужен `min-height`.
- `display: flex` на элементе, у которого текст лежит прямо внутри, без потомка-обёртки: flex влияет только на детей, а текст — это не элемент.
- Пытаются выровнять по вертикали `vertical-align` — это свойство для таблиц и inline-элементов, во flex-раскладке оно не работает.
