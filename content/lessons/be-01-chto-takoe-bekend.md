## Бэкенд — другая сторона запроса

До сих пор вы были клиентом: разметка, стили и `fetch` выполняются в браузере пользователя. Бэкенд (backend) — программа на сервере, которая принимает HTTP-запрос и решает, что ответить. Её исходный код пользователь не видит, поэтому только ей можно доверить секреты.

Четыре обязанности бэкенда:

- **Данные.** Хранить и отдавать: задачи, профили, заказы, комментарии.
- **Правила.** Проверять запрос: цена не подделана, товар есть на складе, прав хватает.
- **Состояние.** Помнить, кто вы, между запросами — через сессии и токены.
- **Секреты.** Держать у себя ключи сторонних сервисов, хеши паролей, строку подключения к базе.

## Три слоя серверного приложения

Это деление вы будете держать в голове весь этап.

**Маршрутизация** (routing) сопоставляет запрос с функцией: `GET /api/tasks/5` → обработчик `get_task(5)`. Логики здесь нет, только «куда передать управление».

**Бизнес-логика** (business logic) отвечает на вопрос «что происходит по сути»: начислить скидку, проверить владельца записи, отправить письмо. Это обычные функции Python, которые ничего не знают про HTTP.

**Хранение** (persistence) читает и пишет данные. Сейчас начнём со словаря в памяти, на следующем этапе — с баз данных.

Связь идёт в одну сторону: маршрут вызывает логику, логика вызывает хранилище. Обратных зависимостей быть не должно, иначе код нельзя проверить отдельно от веба.

## Почему клиенту нельзя доверять

Фронтенд виден целиком: его читают в DevTools. Любой запрос можно повторить через `curl`, вообще не открывая страницу:

```bash
curl -X POST https://shop.example/api/orders \
     -H "Content-Type: application/json" \
     -d '{"item_id": 5, "price": 1}'
```

Сервер обязан сам достать цену товара №5 из своего хранилища. Если он поверит полю `price` из тела запроса — заказ уйдёт за рубль.

Клиентская валидация нужна для удобства: человек сразу видит «введите почту», не дожидаясь ответа сети. Защитой она не является. Правило действует до конца курса: **любые данные из запроса враждебны, пока вы их не проверили.**

## Типичная ошибка: всё в одном обработчике

```python
# плохо: обработчик знает и про хранилище, и про скидки, и про формат ответа
@app.post("/api/orders")
def create_order():
    data = request.get_json()
    product = PRODUCTS[data["item_id"]]
    total = product["price"] * data["qty"]
    if total > 5000:
        total *= 0.9
    ORDERS.append({"item_id": data["item_id"], "total": total})
    return jsonify({"total": total}), 201
```

Правило скидки спрятано внутри HTTP-обработчика. Его нельзя вызвать из теста, из командного скрипта или из другого маршрута — только отправив настоящий запрос.

```python
# хорошо: логика отдельно, обработчик связывает слои
def order_total(product, quantity):
    total = product["price"] * quantity
    return round(total * 0.9, 2) if total > 5000 else total


@app.post("/api/orders")
def create_order():
    data = request.get_json()
    product = PRODUCTS[data["item_id"]]
    total = order_total(product, data["qty"])
    ORDERS.append({"item_id": data["item_id"], "total": total})
    return jsonify({"total": total}), 201
```

`order_total` — чистая функция: на входе данные, на выходе число. Её тестируют одной строкой, а правила скидки меняют в одном месте.
