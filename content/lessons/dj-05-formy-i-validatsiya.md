## Форма проверяет то, что прислал браузер

Всё, что приходит в `request.POST`, можно подменить в DevTools или отправить через curl. Формула безопасности, которую вы знаете с первых уроков: **никогда не доверяйте данным клиента**. Django-форма — это инструмент, который берёт сырые данные, проверяет их и возвращает либо чистые значения, либо список ошибок.

```python
form = PostForm(request.POST)
if form.is_valid():
    post = form.save()          # здесь данные уже проверены
```

## Form против ModelForm

`forms.Form` — обычный набор полей, не связанный с моделью. `forms.ModelForm` наследует поля от модели и умеет сохранять объект.

```python
class PostForm(forms.ModelForm):
    class Meta:
        model = Post
        fields = ["title", "body", "tags"]
```

`Meta.fields` перечисляет, какие поля модели попадут в форму. Явно указывайте список — не пишите `fields = "__all__"`, иначе в форму просочатся поля, которые пользователь менять не должен (например, `author` или `is_published`).

## is_valid() и cleaned_data

`form.is_valid()` запускает валидацию и возвращает `True`/`False`. После успешной проверки чистые, приведённые к нужным типам данные лежат в `form.cleaned_data`. Читайте именно их, а не сырой `request.POST`:

```python
if form.is_valid():
    title = form.cleaned_data["title"]   # проверенное значение
```

Свои правила добавляют методом `clean_<поле>()` или общим `clean()` — например, «дата окончания больше даты начала».

## CSRF: защита от подделки запроса

CSRF (Cross-Site Request Forgery) — атака, при которой чужой сайт заставляет браузер пользователя отправить запрос от его имени. Django защищает от неё токеном. Внутри каждой POST-формы обязательно должен быть тег:

```html
<form method="post">
  {% csrf_token %}
  {{ form.as_p }}
  <button type="submit">Сохранить</button>
</form>
```

> Без `{% csrf_token %}` отправка POST вернёт **403 Forbidden** — `CsrfViewMiddleware` отклонит запрос. Это не баг, а работающая защита.

## Рендер ошибок

`{{ form.as_p }}` выводит поля абзацами и автоматически добавляет текст ошибок рядом с каждым. Для точного контроля рендерят вручную: `{{ field.errors }}` для конкретного поля, `{{ form.non_field_errors }}` для общих. После неудачной отправки форма возвращается с введёнными данными и ошибками — пользователь не теряет текст.

```python
return render(request, "posts/post_form.html", {"form": form})
```

## Типовая ошибка

Сохранять данные, не вызвав `is_valid()`. `form.save()` на непроверенной форме либо упадёт, либо запишет мусор. Вторая ловушка — читать `request.POST["title"]` напрямую вместо `form.cleaned_data`: так вы берёте сырую, непроверенную строку и теряете весь смысл валидации. И третья: `fields = "__all__"` в ModelForm, из-за которой злоумышленник подставляет в POST лишнее поле (массовое присваивание, mass assignment) и меняет то, что менять не должен.
