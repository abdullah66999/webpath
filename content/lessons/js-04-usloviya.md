## if проверяет не «true или false», а истинность

Условие в JavaScript устроено так:

```js
if (balance > 0) {
  /* выполнить, когда условие истинно */
} else {
  /* иначе */
}
```

Но внутри `if` может стоять любое значение — и тогда JS приводит его к булеву типу (truthiness). Все значения делятся на **truthy** (истинные) и **falsy** (ложные).

Falsy ровно восемь: `false`, `0`, `-0`, `0n`, `''` (пустая строка), `null`, `undefined`, `NaN`. Всё остальное — truthy, включая `'0'`, `' '` (строку с пробелом), `[]` и `{}`.

```js
if ('0') { /* выполнится! непустая строка — truthy */ }
if ([])  { /* выполнится! массив — объект */ }
```

Практический вывод: данные из полей ввода приходят строками, и `if (value)` не отличит «пусто» от «ввёл ноль». Проверяйте явно: `if (value !== '')`, а для чисел — после `Number(value)`.

Пустой массив особенно коварен: чтобы проверить, есть ли в нём элементы, нужен `if (items.length > 0)`, а не `if (items)`.

## Цепочка else if и switch

Когда вариантов больше двух, их выстраивают в цепочку `if / else if / else`. Порядок имеет значение: условия проверяются сверху вниз, и первое же срабатывание завершает цепочку.

`switch` — альтернатива для случая, когда одно значение сравнивается с набором конкретных вариантов:

```js
switch (command) {
  case 'save':
    save();
    break;
  case 'delete':
    remove();
    break;
  default:
    unknown(command);
}
```

Две детали. Сравнение в `case` строгое, как `===`: `switch (1)` не совпадёт с `case '1'`. И после каждого `case` нужен `break` — без него выполнение провалится в следующий блок, не проверяя его условие. Диапазоны (`score >= 90`) в `switch` не выразить — это территория `if`.

## Тернарный оператор

`условие ? еслиДа : еслиНет` — единственный оператор с тремя операндами (ternary operator). Он удобен, когда нужно выбрать значение, а не выполнить разные действия:

```js
const status = isPaid ? 'оплачен' : 'ожидает';
const label = count === 1 ? 'товар' : 'товаров';
```

Один тернарный — хорошо. Два вложенных друг в друга — уже ребус; раскладывайте на `if / else`.

## Guard clauses

Сторожевая оговорка (guard clause) — ранний `return` для особого случая в начале функции. Так основная логика остаётся на верхнем уровне вложенности:

```js
function divide(a, b) {
  if (b === 0) return null;  // особый случай разобрали и вышли
  return a / b;              // основная ветка без лишнего else
}
```

Без guard clause получилось бы то же самое, но с `else` и дополнительным уровнем отступа. Чем меньше вложенности, тем легче читать код — и тем меньше шансов пропустить ветку.

## Частые ошибки

- `if (x = 5)` — присваивание вместо сравнения: условие всегда truthy, а `x` испорчен. Сравнение — `===`.
- Пропущенный `break` в `switch`: код выполняется и в следующем `case`.
- `if (items)` для массива — пустой массив truthy; проверяйте `items.length > 0`.
- `if ('0')` — строка из формы с нулём проходит проверку, хотя по смыслу значение пустое.
- Многоэтажные тернарные цепочки `a ? b : c ? d : e` — их невозможно читать, используйте `if`.
