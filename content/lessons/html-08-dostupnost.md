## Доступность — это не только про скринридеры

Доступный (accessible, сокращённо a11y) сайт работает для всех: для человека, который ходит по сайту клавиатурой из-за тремора рук; для дальтоника; для того, кто читает на солнце; для поискового робота, который «видит» страницу примерно как скринридер. Хорошая новость: страница на семантических тегах доступна по умолчанию — большая часть работы делается правильным HTML.

## Нативные элементы делают всё сами

```html
<!-- так не надо -->
<div class="btn" onclick="send()">Отправить</div>

<!-- так надо -->
<button type="button" onclick="send()">Отправить</button>
```

`button` из коробки: получает фокус по Tab, активируется Enter и пробелом, объявляется скринридером как «кнопка», имеет состояние нажатия и стилизуется через `:focus-visible`. У `div` с `onclick` нет ничего из этого — чтобы повторить, придётся писать обработчики клавиатуры и ARIA-роли вручную. Отсюда **первое правило ARIA**: если есть нативный элемент или атрибут с нужной семантикой — используйте его, ARIA не нужен.

То же со ссылками: `<span onclick="перейти()">` должен быть `<a href="...">`.

## Текстовая альтернатива

У каждого `img` — атрибут `alt`, и он зависит от роли картинки:

- **Содержательное изображение** (график, товар, скриншот): `alt` передаёт информацию — «График продаж: 120 заказов в 2024, 340 в 2025». Не «график», а вывод из него.
- **Декорация** (разделитель, узор): `alt=""` — пустая строка, скринридер пропустит картинку. Пропускать сам атрибут нельзя: это ошибка, и часть скринридеров зачитает имя файла.
- **Картинка внутри ссылки**: `alt` описывает действие — «Профиль», а не «аватарка».
- **Картинка с подписью рядом**: подпись уже всё объясняет, `alt` может быть короче или пустым.

## Фокус и клавиатура

Человек без мыши перемещается по странице Tab. Требования простые:

1. Все интерактивные элементы фокусируемые — `a href`, `button`, `input`, `select` делают это нативно.
2. Фокус **виден**: не пишите `outline: none` глобально. Убрали стандартную рамку — нарисуйте свою через `:focus-visible`.
3. Порядок обхода совпадает с логикой: он следует порядку в разметке, а не визуальному (привет, `order` из flexbox).
4. Модальные окна закрываются по Esc и не выпускают фокус наружу, пока открыты.

## Контраст

Отношение контрастности текста к фону — минимум 4.5:1 для обычного текста и 3:1 для крупного (от 24px). Светло-серый `#aaa` на белом — примерно 2.3:1, это провал. Контраст проверяют пипеткой в DevTools или калькулятором WebAIM.

## Когда ARIA всё-таки нужен

ARIA-атрибуты дополняют семантику, которую HTML не передаёт:

```html
<button aria-label="Закрыть меню" aria-expanded="false">✕</button>
<nav aria-label="Основная навигация">…</nav>
<span aria-hidden="true">✦</span>
```

`aria-label` даёт имя элементу без текста (кнопка-иконка). `aria-expanded` сообщает состояние «меню раскрыто/скрыто». `aria-hidden="true"` прячет декорацию от скринридера. Важно: ARIA **описывает** поведение, но не создаёт его — `role="button"` на `div` не сделает его нажимаемым с клавиатуры.

## Типичные ошибки

- **`div` и `span` вместо `button` и `a`** — источник половины проблем с доступностью.
- **`placeholder` как единственная подпись поля.**
- **Убранный `outline`** без видимой замены — клавиатурный пользователь теряется на странице.
- **Кнопка-иконка без `aria-label`** — скринридер прочитает пустоту или имя файла.
- **Отсутствующий `alt`** — не то же самое, что пустой.
