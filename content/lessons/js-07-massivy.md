## Массив — изменяемая структура

Массив (array) хранит упорядоченный список значений. В отличие от строки, он **изменяем**: элементы можно перезаписать, добавить, удалить.

```js
const scores = [10, 42, 7];
scores[0];      // 10 — обращение по индексу
scores.length;  // 3
scores[3] = 99; // массив стал [10, 42, 7, 99]
```

Первое, что нужно усвоить: методы массивов делятся на **мутирующие** (меняют массив на месте) и **возвращающие новый**.

- Мутируют: `push`, `pop`, `shift`, `unshift`, `splice`, `sort`, `reverse`, `fill`.
- Возвращают новый: `map`, `filter`, `slice`, `concat`, `toSorted`, `toReversed`.

Если нужно сохранить оригинал — сначала скопируйте: `const copy = [...scores]` или `scores.slice()`.

## map — преобразовать каждый элемент

```js
const prices = [100, 250];
const labels = prices.map((p) => p + ' руб.'); // ['100 руб.', '250 руб.']
```

`map` применяет функцию к каждому элементу и возвращает новый массив той же длины. Исходный не трогается.

Рядом стоит `forEach` — он делает то же, но возвращает `undefined`. Собирать результат через `forEach` нельзя, для этого есть `map`.

## filter — отобрать подходящие

```js
const cheap = prices.filter((p) => p < 200); // [100]
```

Функция-условие возвращает `true`/`false`; в новый массив попадают элементы с `true`. Пустой результат — нормальный исход, а не ошибка.

## reduce — свернуть в одно значение

```js
const total = prices.reduce((acc, p) => acc + p, 0); // 350
```

`acc` — аккумулятор, в него складывается промежуточный результат. Вторым аргументом передают стартовое значение — всегда передавайте его, иначе для пустого массива `reduce` бросит ошибку, а для непустого возьмёт первым значением элемент массива.

## find, some, every, includes

```js
prices.find((p) => p > 200);  // 250 — первый подходящий, иначе undefined
prices.some((p) => p > 200);  // true — есть ли хотя бы один
prices.every((p) => p > 50);  // true — все ли подходят
prices.includes(100);         // true — проверка по значению
```

## sort — две ловушки в одном методе

`sort()` **мутирует** массив и по умолчанию сравнивает элементы **как строки**:

```js
[10, 9, 2].sort(); // [10, 2, 9] — потому что '10' < '2' лексикографически
```

Для чисел нужна функция-компаратор, а для сохранения оригинала — копия:

```js
const asc = [...scores].sort((a, b) => a - b);   // по возрастанию
const desc = [...scores].sort((a, b) => b - a);  // по убыванию
```

Компаратор возвращает отрицательное число, если `a` должен идти раньше `b`, и положительное — если позже.

## Копия против мутации

Два главных правила, которые спасают от «массив сам изменился»:

1. Массивы и объекты передаются по ссылке: `const b = a` не копирует данные — `b` и `a` смотрят на один массив.
2. Сравнение `===` проверяет ссылку, а не содержимое: `[1, 2] === [1, 2]` даёт `false`. Сравнивайте по элементам или через `JSON.stringify(a) === JSON.stringify(b)`.

## Частые ошибки

- `scores.sort()` испортил исходный массив, от которого зависел другой код.
- `sort()` без компаратора на числах: `[10, 2, 9]`.
- Ожидание результата от `forEach` или от `map` «на месте» — `map` возвращает новый массив, старый не меняется.
- `[...nested]` копирует только верхний уровень: вложенные объекты остаются общими (поверхностная копия).
- `indexOf` для поиска объекта — не сработает, объекты сравниваются по ссылке; используйте `find`.
