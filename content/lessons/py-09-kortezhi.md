## Кортеж — неизменяемая коллекция

Кортеж (tuple) — упорядоченная **неизменяемая** коллекция. Индексация, срезы, `len()`, `in` и склейка работают как у списка, но элемент нельзя заменить:

```python
point = (3, -7, 5)
print(point[0])      # 3
print(point[-1])     # 5
print(point[1:])     # (-7, 5)
print(len(point))    # 3
print(-7 in point)   # True
```

Попытка присвоить элементу новое значение заканчивается одинаково: `point[0] = 10` даёт `TypeError: 'tuple' object does not support item assignment`.

## Кортеж создаёт запятая, а не скобки

```python
t1 = (5)     # это int 5, а не кортеж
t2 = (5,)    # кортеж из одного элемента
t3 = 5,      # тоже кортеж: скобки необязательны
print(type(t1))   # <class 'int'>
print(type(t2))   # <class 'tuple'>
print(t3)         # (5,)
```

Запятая после единственного значения обязательна — без неё Python просто вычислит выражение в скобках. Пустой кортеж — `()` или `tuple()`. Из любой последовательности кортеж делает `tuple()`: `tuple("abc")` даст `('a', 'b', 'c')`.

## Распаковка

```python
x, y, z = (3, -7, 5)
print(x, y, z)    # 3 -7 5
```

Слева должно быть ровно столько имён, сколько элементов справа. Не совпало — `ValueError`: `too many values to unpack`, если значений больше, и `not enough values to unpack`, если меньше.

Распаковка работает с любым итерируемым объектом, а звёздочка забирает остаток:

```python
first, *tail = [10, 20, 30, 40]
print(first)    # 10
print(tail)     # [20, 30, 40] — всегда список, даже если справа кортеж

first, *middle, last = [10, 20, 30, 40, 50]
print(middle)   # [20, 30, 40]
```

Обмен значениями пишется в одну строку и без временной переменной:

```python
left, right = "A", "B"
left, right = right, left
print(left, right)    # B A
```

## Неизменяемость не абсолютна

Если внутри кортежа лежит изменяемый объект, его содержимое можно править:

```python
profile = ("Аня", ["python", "sql"])
profile[1].append("flask")
print(profile)    # ('Аня', ['python', 'sql', 'flask'])
```

Привязка кортежа не изменилась — он по-прежнему ссылается на тот же список. Изменилось содержимое списка. Побочный эффект: такой кортеж перестаёт быть хешируемым и уже не годится в ключи словаря.

## Когда кортеж вместо списка

- **Нужен ключ словаря или элемент множества.** Список нехешируемый, кортеж подходит: `distances = {("Москва", "Казань"): 820}`.
- **Запись фиксированной структуры.** `(имя, возраст, город)` — это строка таблицы, а не «набор чего попало». Случайно добавить элемент не получится.
- **Функция возвращает несколько значений.** `return min_value, max_value` на самом деле возвращает кортеж.
- **Данные не должны меняться.** Координаты, дата, конфигурация — неизменяемость защищает от случайной правки.

Кортеж чуть быстрее и компактнее списка, но выбирают его не ради микрооптимизации, а ради смысла: «этот набор значений постоянен».

## Операции и методы

```python
nums = (1, 2, 2, 3)
print(nums.count(2))    # 2
print(nums.index(3))    # 3
print(nums + (4,))      # (1, 2, 2, 3, 4)
print(nums * 2)         # (1, 2, 2, 3, 1, 2, 2, 3)
print(sorted(nums))     # [1, 2, 2, 3] — возвращает список
```

Своих методов у кортежа два: `count()` и `index()`. Остальное делают встроенные функции. Сравнение лексикографическое: `(1, 5) < (2, 0)` — `True`, потому что сначала сравниваются первые элементы.

## Типичные ошибки

- `(5)` вместо `(5,)` — получили число, а не кортеж.
- Пытаются изменить элемент: `t[0] = 1` даёт `TypeError`.
- Кладут в кортеж список и используют его как ключ словаря: `TypeError` с текстом про `unhashable type: 'list'`.
- Берут кортеж для коллекции, которая должна расти: `append()` у него нет.
- Забывают, что звёздочка всегда собирает список: после `first, *tail = (1, 2, 3)` в `tail` лежит `[2, 3]`, а не кортеж.
- Распаковывают в неверное число имён и ловят `ValueError` вместо данных.
