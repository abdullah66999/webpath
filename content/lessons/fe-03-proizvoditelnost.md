## Скорость — это не косметика

Половина посетителей уходит со страницы, которая грузится дольше трёх секунд. Медленный сайт хуже ранжируется в поиске, а на мобильном интернете каждый лишний килобайт — деньги пользователя. Производительность измеряют, а не оценивают на глаз.

## Core Web Vitals

Google свёл удобство загрузки в три метрики — **Core Web Vitals**:

- **LCP** (Largest Contentful Paint) — время до отрисовки самого крупного элемента первого экрана. Хорошо до 2,5 с.
- **INP** (Interaction to Next Paint) — задержка между действием пользователя и реакцией интерфейса. Хорошо до 200 мс. Заменил собой FID в 2024 году.
- **CLS** (Cumulative Layout Shift) — суммарная величина неожиданных сдвигов вёрстки. Хорошо до 0,1.

Измеряют двумя способами. **Лабораторный** — Lighthouse в DevTools: страница открывается один раз в идеальных условиях. **Полевой** — PageSpeed Insights и отчёт CrUX: данные реальных пользователей за 28 дней на 75-м перцентиле. В поиск смотрят на полевые, поэтому лаборатория — инструмент отладки, а не приговор.

## Lighthouse

Открываете DevTools → вкладка Lighthouse → выбираете Performance → Analyze. Отчёт покажет метрики, их цвет и список конкретных замечаний: «изображение без размеров», «неиспользуемый JavaScript», «долгий ответ сервера». Полезнее смотреть не на балл, а на список возможностей (Opportunities) — там написано, сколько миллисекунд экономит каждое исправление.

Прогоняйте Lighthouse в режиме инкогнито: расширения браузера добавляют свой JavaScript и портят цифры.

## Вес страницы

Средняя страница весит около 2,5 МБ, и больше половины этого объёма — картинки. Порядок действий:

1. Современный формат: WebP или AVIF вместо JPEG и PNG, экономия 25–50%.
2. Правильный размер: не грузите 4000 пикселей туда, где на экране 400.
3. Шрифты: подключать два начертания, а не восемь; `font-display: swap`, чтобы текст был виден сразу.
4. JavaScript: каждая библиотека тянет зависимости. Перед установкой посмотрите размер на bundlephobia.

## Ленивая загрузка и приоритеты

```html
<img src="hero.webp" width="1200" height="600" alt="Главный экран" fetchpriority="high">
<img src="photo-07.webp" width="640" height="480" alt="Фото в галерее" loading="lazy">
```

`loading="lazy"` откладывает загрузку, пока картинка не приблизится к экрану. Но для главного изображения первого экрана он вреден: браузер узнаёт о нём позже, и LCP растёт. Такому изображению вместо ленивой загрузки ставят `fetchpriority="high"`.

Обязательны `width` и `height` — по ним браузер заранее резервирует место, и вёрстка не прыгает, когда картинка доезжает. Это и есть профилактика CLS.

## Кэш

Кэш браузера управляется заголовком `Cache-Control`. Стратегия стандартная:

- `index.html` — `no-cache`: браузер каждый раз спрашивает, не обновился ли файл;
- файлы с хэшем в имени (`app.3f2a1c1b.js`) — `max-age=31536000, immutable`: кэшируются на год, потому что при изменении содержимого меняется и имя.

Именно хэш в именах, который добавляет сборщик, делает такую схему безопасной. Дополнительно файлы раскладывают ближе к пользователю через CDN.

## Критический CSS и блокирующие ресурсы

Браузер не рисует страницу, пока не скачает и не разберёт CSS из `<link>`: это блокирующий ресурс. Два приёма:

- стили, нужные для первого экрана, встраивают прямо в `<head>` — это и есть критический CSS;
- JavaScript не должен блокировать отрисовку: `<script defer>` выполняется после разбора документа.

```html
<head>
  <link rel="preconnect" href="https://fonts.gstatic.com" crossorigin>
  <style>/* критический CSS первого экрана */</style>
  <link rel="stylesheet" href="/assets/full.css" media="print" onload="this.media='all'">
  <script src="/assets/app.js" defer></script>
</head>
```

## Типичные ошибки

- `loading="lazy"` на картинке первого экрана — LCP становится хуже.
- Картинки без `width` и `height` — вёрстка прыгает, растёт CLS.
- Один бандл на всё приложение: пользователь главной страницы качает код личного кабинета. Лечится динамическим импортом.
- `Cache-Control: max-age=31536000` на `index.html` — посетитель годами видит старую версию.
- Оптимизировали по баллу Lighthouse, а не по метрикам реальных пользователей.
