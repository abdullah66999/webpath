## Сначала — честный разговор

В современном JavaScript классы нужны **реже**, чем в Python или Java. Здесь нет культуры «всё есть объект класса»: компоненты интерфейсов пишут функциями, утилиты — функциями, данные хранят обычными объектами и массивами. Большинство кода, который вы встретите во фронтенде и Node.js, обходится без единого `class`.

Класс становится полезен, когда появляется **много похожих сущностей с общим поведением**: товары в каталоге, игровые персонажи, виджеты, обёртки над API. Тогда он собирает «данные + методы» в одном месте и позволяет создавать десятки экземпляров одной строкой. Знать синтаксис нужно и потому, что чужой код (библиотеки, UI-фреймворки) классами пользуется активно.

## Класс, конструктор, this

```js
class Product {
  constructor(name, price) {
    this.name = name;
    this.price = price;
  }

  label() {
    return `${this.name}: ${this.price} руб.`;
  }
}

const tea = new Product('чай', 250);
tea.label(); // 'чай: 250 руб.'
```

`new` создаёт пустой объект, `constructor` наполняет его, а `this` указывает на создаваемый экземпляр. Методы не копируются в каждый объект — они живут в прототипе и общие для всех экземпляров. Забудьте слово `function` внутри класса: методы объявляются сразу по имени.

## Потеря this — главная ловушка

Код класса выполняется в строгом режиме. Если метод «оторвать» от объекта, `this` станет `undefined`:

```js
const log = tea.label;
log(); // TypeError: Cannot read properties of undefined
```

Это происходит всякий раз, когда метод передают как колбэк: `setTimeout(tea.label, 100)`, `button.addEventListener('click', counter.inc)`. Функция уходит одна, объект теряется. Два лекарства:

```js
setTimeout(() => tea.label(), 100);   // стрелка-обёртка
button.addEventListener('click', counter.inc.bind(counter)); // bind
```

## extends и super

```js
class Sale extends Product {
  constructor(name, price, percent) {
    super(name, price);   // вызов родительского конструктора
    this.percent = percent;
  }

  label() {
    return super.label() + ' (скидка)'; // переопределили и позвали родителя
  }
}
```

В подклассе `super(...)` **обязан** вызываться до любого обращения к `this` — иначе ReferenceError. Наследование проверяется через `instanceof`: `new Sale(...) instanceof Product` даст `true`, потому что `instanceof` смотрит на всю цепочку прототипов.

## Когда класс не нужен

- Одна конфигурация приложения — объектный литерал `{ theme: 'dark' }` и пара функций.
- Разовое действие — просто функция.
- «Набор утилит» со static-методами — почти всегда обычные функции модуля.
- Наследование глубже одного-двух уровней — сигнал пересмотреть проект; композиция (функция принимает объект с данными) проще и гибче.

Хорошая проверка: если вы не собираетесь создавать **много экземпляров** и у них нет общего изменяемого поведения — скорее всего, хватит функции и объекта.

## Частые ошибки

- Метод передан как колбэк без `bind` — `this` потерян, код падает в самом неожиданном месте.
- `super()` забыт или вызван после `this` в конструкторе подкласса.
- Ожидание, что класс даёт приватность: поля публичны, настоящая приватность — имена с `#` (`#balance`).
- Класс «как в Java» ради класса: пустой конструктор и один метод почти всегда заменяются функцией.
- `typeof tea === 'Product'` — не работает: typeof для экземпляра всегда `'object'`, используйте `instanceof`.
