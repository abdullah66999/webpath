## Событие — сигнал от браузера

Клик, нажатие клавиши, наведение курсора, отправка формы, прокрутка — всё это **события** (events). JavaScript не опрашивает страницу в цикле, а подписывается на сигналы: «когда случится вот это — выполни мою функцию». Такой стиль называют событийным (event-driven).

## addEventListener и объект события

```js
const button = document.querySelector('#save');

button.addEventListener('click', function (event) {
  console.log(event.type);          // 'click'
  console.log(event.target);        // элемент, где событие случилось
  console.log(event.currentTarget); // элемент, на котором висит обработчик
});
```

`addEventListener` принимает имя события, функцию-обработчик и необязательные настройки. На один элемент можно повесить сколько угодно обработчиков — они выполнятся по очереди добавления. Свойство `onclick` ведёт себя хуже: повторное присваивание затирает предыдущий обработчик, поэтому в реальном коде его не используют.

В обработчик приходит объект `event`. Самые нужные поля:

- `target` — самый глубокий элемент, в котором событие возникло;
- `currentTarget` — элемент, чей обработчик сейчас выполняется;
- `key` — нажатая клавиша для `keydown`;
- `preventDefault()` — отменить действие браузера по умолчанию;
- `stopPropagation()` — остановить всплытие.

## Всплытие и погружение

Клик по кнопке внутри списка — это не одно событие, а три. Сначала срабатывает **погружение** (capturing): событие идёт от `document` вниз к цели, обработчики на этом пути обычно молчат. Затем **всплытие** (bubbling): событие поднимается от цели вверх, и обработчики вызываются на кнопке, потом на `li`, потом на `ul`, потом на `body`.

Именно поэтому `event.target` и `event.currentTarget` — разные вещи: цель одна, а обработчиков на пути несколько.

Всплывают не все события: `focus`, `blur`, `mouseenter` и `scroll` на элементе остаются на месте. Для фокуса есть всплывающие двойники `focusin` и `focusout`.

## Делегирование

Всплытие даёт приём, который вы будете использовать постоянно — **делегирование** (event delegation). Вместо обработчика на каждой кнопке вешают один на общий контейнер и внутри смотрят, по чему именно кликнули:

```js
list.addEventListener('click', function (event) {
  const button = event.target.closest('.del');
  if (!button) return;              // кликнули мимо кнопки
  button.closest('li').remove();    // удаляем весь пункт
});
```

Выигрыш тройной: один слушатель вместо тридцати, меньше памяти и — главное — пункты, добавленные в список позже, работают сразу, ничего переприсваивать не нужно. Обратная сторона: `stopPropagation()` в чужом обработчике внутри контейнера может сломать вашу логику, а слишком «жадный» контейнер ловит лишние клики — отсюда обязательная проверка `if (!button) return;`.

## preventDefault

У многих событий есть действие по умолчанию: ссылка переходит по адресу, форма перезагружает страницу, правый клик открывает меню браузера. `event.preventDefault()` его отменяет.

```js
form.addEventListener('submit', function (event) {
  event.preventDefault();   // без этой строки страница перезагрузится
  // и весь ваш JavaScript начнёт работу заново
});
```

Забытый `preventDefault` в обработчике `submit` — самый частый баг новичка: код как будто выполняется, потом страница мигает, и состояние пропадает.

## Типичные ошибки

- Обработчик в цикле на каждую кнопку: динамически добавленные элементы остаются «мёртвыми».
- `removeEventListener(fn)` не снимает слушатель, если `fn` — новая анонимная функция. Храните ссылку на ту же функцию, которую добавляли.
- `stopPropagation()` «на всякий случай» — ломает делегирование выше по дереву.
- Обработчик висит на элементе, которого ещё нет в DOM: скрипт выполнился раньше разметки.
