## npm и package.json

**npm** (Node Package Manager) — менеджер пакетов, который ставится вместе с Node.js. Node.js нужен не для того, чтобы писать сервер прямо сейчас, а как среда, в которой работают инструменты разработки: сборщики, линтеры, локальные серверы.

**package.json** — паспорт проекта. В нём лежат имя, версия, команды и список зависимостей:

```json
{
  "name": "my-landing",
  "private": true,
  "version": "0.1.0",
  "type": "module",
  "scripts": {
    "dev": "vite",
    "build": "vite build",
    "preview": "vite preview"
  },
  "devDependencies": {
    "vite": "^5.4.0"
  }
}
```

`dependencies` — пакеты, нужные в рантайме. `devDependencies` — только для разработки: сборщик, линтер, типы. Разделение важно при установке на сервере: там dev-пакеты не нужны.

## Установка зависимостей

```bash
npm install lodash      # добавить пакет и записать его в package.json
npm install             # поставить всё, что перечислено в package.json
npm uninstall lodash    # убрать пакет
```

Всё скачивается в папку `node_modules`. Её **никогда не коммитят**: она весит сотни мегабайт и полностью восстанавливается командой `npm install`. Именно поэтому после `git clone` первое действие — `npm install`, и только потом `npm run dev`.

Файл `package-lock.json` фиксирует точные версии всего дерева зависимостей, и вот его коммитить обязательно: без него у коллеги и на сервере установятся другие версии.

Версии пакетов описывает **semver**: `MAJOR.MINOR.PATCH`. Запись `^1.4.2` означает «от 1.4.2 до 2.0.0, не включая двойку» — то есть минорные и патч-обновления ставить можно, ломающие изменения нельзя. `~1.4.2` ещё строже: только патчи.

## Что такое сборка

Браузер умеет загружать модули, но в реальном проекте их сотни, и каждый — отдельный запрос. **Сборщик** (bundler) делает пять вещей:

- склеивает модули в несколько больших файлов — меньше запросов;
- минимизирует код: убирает пробелы, комментарии, сокращает имена переменных;
- добавляет в имена файлов хэш содержимого — основу кэширования;
- обрабатывает ассеты: картинки, шрифты, CSS;
- переписывает новый синтаксис под старые браузеры.

Результат попадает в папку `dist` — именно её выкладывают на хостинг. Исходники из `src` не публикуют.

## Vite: dev-сервер и HMR

```bash
npm create vite@latest my-landing -- --template vanilla
cd my-landing
npm install
npm run dev      # http://localhost:5173
npm run build    # собирает dist
npm run preview  # показывает собранное локально
```

Vite в режиме разработки не склеивает модули, а отдаёт их как есть — поэтому старт занимает секунду. Изменения подхватывает **HMR** (Hot Module Replacement): сборщик подменяет в браузере только изменившийся модуль, без полной перезагрузки страницы и без потери состояния интерфейса.

`scripts` в package.json — псевдонимы команд. `npm run dev` запускает `vite` из локальной папки `node_modules/.bin`, поэтому ставить инструменты глобально не нужно: у каждого проекта своя версия.

## Типичные ошибки

- Закоммитили `node_modules` — репозиторий раздулся до сотен мегабайт.
- После `git clone` сразу `npm run dev` без `npm install` — «vite: command not found».
- Правят файлы в `dist`: следующая сборка их затрёт. Источник всегда в `src`.
- Сборщик записали в `dependencies` вместо `devDependencies`.
- Пакет поставили глобально через `-g`, а проект требует локальную версию — поведение расходится с документацией.
