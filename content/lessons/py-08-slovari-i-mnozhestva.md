## Словарь: пары «ключ — значение»

Словарь (dict) находит значение по ключу, а не перебором, как список. Это главная причина его популярности: JSON, настройки, кэш, подсчёт частот — всё это словари.

```python
user = {"name": "Аня", "age": 30, "city": "Казань"}
print(user["name"])     # Аня
```

Ключом может быть любой неизменяемый объект: строка, число, кортеж. Список ключом быть не может — он нехешируемый. Значением становится что угодно. Пустой словарь — `{}` или `dict()`. С Python 3.7 словари сохраняют порядок добавления ключей.

## KeyError против get

```python
user = {"name": "Аня"}
print(user.get("age"))        # None — ошибки нет
print(user.get("age", 0))     # 0 — значение по умолчанию
print("name" in user)         # True
print(user["age"])            # KeyError: 'age'
```

`in` проверяет **ключи**, а не значения. Оператор `[]` уместен, когда отсутствие ключа — это ошибка программы; `get()` — когда отсутствующий ключ нормален и у него есть разумное значение по умолчанию.

Запись создаёт и обновляет ключ одним и тем же способом:

```python
user = {"name": "Аня"}
user["age"] = 30                   # добавили
user["age"] = 31                   # перезаписали
print(user)                        # {'name': 'Аня', 'age': 31}

removed = user.pop("age", None)    # удаляет и возвращает, без KeyError
print(removed, user)               # 31 {'name': 'Аня'}
```

## Обход словаря

```python
user = {"name": "Аня", "age": 30}

for key in user:                    # только ключи
    print(key, user[key])

for key, value in user.items():     # пары — так пишут почти всегда
    print(key, value)

list(user.keys())      # ['name', 'age']
list(user.values())    # ['Аня', 30]
```

`keys()`, `values()` и `items()` возвращают не списки, а представления (view): они отражают изменения словаря на лету. Оберните в `list()`, если нужен именно список.

## Менять словарь во время итерации нельзя

```python
scores = {"a": 1, "b": 5, "c": 2}
for key in scores:
    if scores[key] < 3:
        del scores[key]        # RuntimeError
```

Python бросает `RuntimeError: dictionary changed size during iteration`. Обходите копию ключей — `for key in list(scores):` — или собирайте новый словарь. У списков такой защиты нет: там удаление во время обхода молча пропускает элементы, и это ещё хуже.

## Словарь одним выражением

```python
prices = {"яблоко": 120, "груша": 90}
discounted = {name: round(price * 0.9, 2) for name, price in prices.items()}
```

Та же идея, что и у list comprehension, только с парами ключ-значение.

## Множества

Множество (set) хранит уникальные элементы без порядка:

```python
tags = {"python", "flask", "python"}
len(tags)          # 2 — дубль исчез
sorted(tags)       # ['flask', 'python']
```

Самый частый приём — убрать повторы: `unique = list(set(items))`. Порядок при этом теряется; если он важен, сортируйте результат или используйте `dict.fromkeys(items)`, который порядок сохраняет.

Операции читаются как в математике:

```python
a = {1, 2, 3}
b = {3, 4}
a | b        # объединение: {1, 2, 3, 4}
a & b        # пересечение: {3}
a - b        # разность: {1, 2}
a <= b       # проверка на подмножество
```

Добавляют элементы через `add()`, убирают через `discard()` — он не бросает ошибку, если элемента нет, в отличие от `remove()`. Пустое множество создаётся только вызовом `set()`.

## Подсчёт частот

```python
words = ["яблоко", "груша", "яблоко"]
counts = {}
for word in words:
    counts[word] = counts.get(word, 0) + 1
print(counts)      # {'яблоко': 2, 'груша': 1}
```

Строка `counts.get(word, 0) + 1` — идиома: берём текущее значение или ноль и увеличиваем. Самое частое слово даёт `max(counts, key=counts.get)`. В стандартной библиотеке есть готовый `collections.Counter` — он умеет то же и ещё `most_common(3)`.

## Типичные ошибки

- Обращение к необязательному ключу через `[...]` вместо `.get()` — и `KeyError` в продакшене.
- `{}` в ожидании пустого множества: это пустой словарь.
- Удаление ключей из словаря прямо в цикле по нему.
- Список как ключ словаря: `TypeError: unhashable type: 'list'`.
- Ожидание, что множество хранит порядок вставки. Порядка у него нет, для порядка есть словарь.
