## Зачем нужен класс

Функции работают с данными, которые им передали. Но у сущности из предметной области — товара, пользователя, заказа — есть **состояние**, которое живёт между вызовами: цена, имя, список позиций. Таскать его аргументами в каждую функцию неудобно. Класс (class) объединяет данные и операции над ними в один объект.

```python
class Product:
    def __init__(self, name, price):
        self.name = name
        self.price = price

    def discounted(self, percent):
        return self.price * (1 - percent / 100)

tea = Product("Чай", 320)      # создали объект (экземпляр, instance)
print(tea.name)                # Чай
print(tea.discounted(10))      # 288.0
```

`class Product` описывает устройство: что будет в объекте и что он умеет. `Product("Чай", 320)` создаёт конкретный экземпляр. Из одного класса можно сделать сколько угодно объектов — у каждого свои данные.

## __init__ и self

`__init__` — метод-инициализатор: Python вызывает его сразу после создания объекта и передаёт аргументы из скобок. `self` — это **сам экземпляр**, первый параметр любого метода. При вызове `tea.discounted(10)` Python сам подставляет `tea` на место `self`: вы пишете два аргумента, метод видит три.

`self.name = name` записывает значение в **атрибут экземпляра** (instance attribute) — в «рюкзак» конкретного объекта. Атрибуты, созданные в `__init__`, доступны снаружи через точку: `tea.price`, и внутри методов — через `self.price`.

`self` — не ключевое слово, а соглашение. Технически параметр можно назвать как угодно, но не делайте так: весь мир пишет `self`, и ваш будущий коллега (и вы сами через год) будет искать именно его.

## Методы меняют состояние

Метод — функция внутри класса. Полезная привычка: метод читает и меняет `self`, ничего не зная о внешнем мире.

```python
class Cart:
    def __init__(self):
        self.items = []

    def add(self, name, price):
        self.items.append((name, price))

    def total(self):
        return sum(price for _, price in self.items)

cart = Cart()
cart.add("Хлеб", 45)
cart.add("Молоко", 80)
print(cart.total())    # 125
```

Обратите внимание: `self.items = []` создаётся **внутри `__init__`**, поэтому у каждой корзины свой список.

## Атрибуты класса и общая ловушка

Атрибут, объявленный прямо в теле класса, принадлежит **классу**, а не экземплярам, — он один на всех:

```python
class Team:
    members = []            # атрибут класса — общий список

    def __init__(self, name):
        self.name = name

first = Team("Первая")
first.members.append("Аня")

second = Team("Вторая")
print(second.members)       # ['Аня'] — команды разные, список один!
```

Запись `first.members.append(...)` не создаёт атрибут экземпляра: `first.members` находит список класса, и `append` меняет его для всех. Классические атрибуты годятся для **констант** и значений по умолчанию, которые не изменяются:

```python
class Circle:
    PI = 3.14159            # константа — одна на все круги, это нормально

    def __init__(self, radius):
        self.radius = radius

    def area(self):
        return Circle.PI * self.radius ** 2
```

Правило: **всё изменяемое (списки, словари, счётчики) — только в `self` внутри `__init__`**. Атрибут класса — только для неизменяемого и общего.

## Частые ошибки

- Забыли `self` у атрибута: `name = name` вместо `self.name = name` — переменная останется локальной и исчезнет.
- Забыли `self` в списке параметров метода: `def area(radius)` — при вызове `radius` попадёт экземпляр, а настоящий аргумент станет лишним и упадёт с `TypeError`.
- Вызвали метод без скобок: `print(cart.total)` напечатает `<bound method ...>`, а не сумму. Скобки обязательны.
- Присвоили атрибуту класса значение через экземпляр и удивились, что «сломалось у соседа»: `first.members = [...]` создаст атрибут экземпляра, а `first.members.append(...)` меняет общий.
