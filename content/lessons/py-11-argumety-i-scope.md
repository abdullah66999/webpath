## Аргументы: когда заранее не знаете, сколько их будет

В прошлый раз `def price(amount, discount=0)` ждала ровно два значения. Но функция логирования не знает, сколько строк ей передадут, а обёртка над API не знает, какие именно параметры придут. Для этого есть две конструкции: `*args` и `**kwargs`.

```python
def total(*prices):
    return sum(prices)

total()            # 0 — аргументов нет, prices пуст
total(120)         # 120
total(120, 45, 90) # 255
```

Звёздочка перед `*prices` говорит: «собери все лишние позиционные аргументы в **кортеж** (tuple)». Внутри функции `prices` — обычный кортеж, его можно обходить циклом, передавать в `sum()`.

`**kwargs` делает то же для именованных аргументов, но собирает **словарь** (dict):

```python
def register(username, **meta):
    print(username, meta)

register("anya", city="Питер", age=24)
# anya {'city': 'Питер', 'age': 24}
```

## Порядок параметров и keyword-only

Полная сигнатура выглядит так: сначала обычные параметры (в том числе со значениями по умолчанию), потом `*args` или одиночная `*`, затем keyword-only параметры и в самом конце `**kwargs`. Всё, что стоит **после `*`**, можно передать только по имени — это keyword-only параметры:

```python
def connect(host, port=5432, *, timeout=10, **options):
    ...

connect("db.example.com", 6543, timeout=3)  # хорошо
connect("db.example.com", 6543, 3)          # TypeError: 3 — лишний позиционный
```

Зачем это нужно: `timeout=3` читается явно, а защиту от «третьего числа непонятно о чём» берёт на себя интерпретатор. Звёздочка — это не только упаковка, но и запрет.

Обратная операция — **распаковка** (unpacking). Тот же список можно разложить в позиционные аргументы:

```python
sizes = [3, 7, 5]
print(max(*sizes))   # то же, что max(3, 7, 5)
```

## Где живёт переменная: LEGB

Переменная, созданная внутри функции, существует только внутри неё (scope — область видимости). Когда Python встречает имя, он ищет его по цепочке **LEGB**:

1. **L**ocal — локальная область текущей функции;
2. **E**nclosing — объемлющие функции, если функция вложена;
3. **G**lobal — уровень модуля (файла);
4. **B**uilt-in — встроенные имена вроде `len` и `print`.

```python
role = "гость"            # Global

def dashboard():
    role = "админ"        # Local — своя переменная, глобальная не пострадала
    return role

print(dashboard())        # админ
print(role)               # гость
```

Присваивание внутри функции **создаёт локальную переменную**, даже если такое имя уже есть снаружи. Чтение — идёт по цепочке LEGB. Отсюда классическая ошибка: `count += 1` внутри функции без объявления падает с `UnboundLocalError` — Python считает `count` локальной, а она ещё не создана.

## global и nonlocal

`global` приказывает работать с переменной модуля, `nonlocal` — с переменной объемлющей функции:

```python
def make_counter():
    count = 0
    def counter():
        nonlocal count   # меняем переменную из make_counter
        count += 1
        return count
    return counter
```

`global` в прикладном коде — почти всегда запах: функция, которая молча меняет состояние модуля, непроверяема. Возвращайте значение через `return` и передавайте его аргументом. `global` оправдан разве что для констант и кэшей уровня модуля. `nonlocal` — рабочий инструмент замыканий (closures): пара `make_counter`/`counter` выше хранит состояние между вызовами без единой глобальной переменной.
