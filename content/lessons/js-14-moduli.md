## Почему одного файла мало

Пока проект умещается в один `app.js`, всё хорошо. Как только файлов становится три, начинаются проблемы: все переменные живут в одной глобальной области, два файла могут объявить одно и то же имя, зависимости между кусками кода нигде не записаны, а порядок подключения `<script>` приходится держать в голове.

**Модуль** (module) решает это: каждый файл — отдельная область видимости, которая явно говорит, что отдаёт наружу и что берёт у других.

## export и import

```js
// format.js
export const CURRENCY = '₽';

export function formatPrice(value) {
  return value.toFixed(2) + ' ' + CURRENCY;
}

export default function createFormatter() {
  return { formatPrice };
}
```

```js
// main.js
import createFormatter, { formatPrice, CURRENCY as CUR } from './format.js';
```

Правила простые, но путают постоянно:

- **Именованный экспорт** (named export) — их в файле сколько угодно, импортируются в фигурных скобках ровно под своими именами.
- **Экспорт по умолчанию** (default export) — не больше одного на модуль, импортируется без скобок под любым именем.
- Путь пишут с расширением: в браузере `'./format'` не сработает, только `'./format.js'`.

Модуль выполняется **один раз**, при первом импорте. Дальше все, кто его импортировал, получают одни и те же значения. Внутри модуля действует строгий режим, а переменные не попадают в `window`.

## Как это видит браузер

```html
<script type="module" src="./main.js"></script>
```

Браузер сам строит граф зависимостей: загружает `main.js`, находит в нём `import`, идёт за каждым файлом, и так до листьев. Модульный скрипт по умолчанию отложен, как `defer`: он выполняется после разбора документа, поэтому `document.querySelector` внутри уже работает.

И здесь главная засада. Откройте `index.html` двойным кликом — и в консоли появится ошибка CORS: модули разрешено загружать только по протоколам `http`, `https` или `data`, а двойной клик даёт `file://`. Страница будет пустой, хотя код правильный. Лечится одним локальным сервером в папке проекта:

```bash
python -m http.server 8000    # если установлен Python
npx serve .                   # если установлен Node.js
```

Дальше открываете `http://localhost:8000`. В VS Code то же самое делает кнопка Live Server.

## Типы модулей

- **ESM** — `import`/`export`. Стандарт языка, работает и в браузере, и в современном Node.js.
- **CommonJS** — `require()` и `module.exports`. Старый формат Node.js; в браузере функции `require` не существует.
- **IIFE и UMD** — файл-обёртка, который сам регистрирует себя в глобальной переменной. Так распространяли библиотеки до сборщиков; подключается обычным `<script>`.

Если в туториале вы видите `require`, перед вами Node.js-код, а не браузерный.

## Tree-shaking и зачем нужен сборщик

Импорты в ESM **статичны**: они видны до выполнения кода. Анализатор проходит по графу модулей и вырезает то, что никто не импортировал, — это и есть tree-shaking («встряхивание дерева»: лишнее опадает). С `require` так не получится — он вычисляется во время выполнения.

Сборщик (bundler) делает четыре вещи: склеивает десятки мелких файлов в несколько больших (каждый файл — отдельный HTTP-запрос), минимизирует код, добавляет в имена файлов хэш для кэширования и переписывает новый синтаксис под старые браузеры. Всё это вы настроите на следующем уроке через npm и Vite.

## Типичные ошибки

- Открыли `index.html` двойным кликом — CORS заблокировал модули, страница пустая.
- Забыли `.js` в пути импорта.
- Перепутали default и именованный экспорт: `import formatPrice from './format.js'` не найдет именованный экспорт.
- Импортировали имя, которого в модуле нет, — синтаксическая ошибка ещё до запуска кода.
- Рассчитываете на глобальную переменную из соседнего файла: в модуле её не существует.
