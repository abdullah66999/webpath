## Что браузер умеет проверять сам

```html
<input type="email" name="mail" required>
<input type="number" name="age" min="14" max="120">
<input name="login" minlength="3" maxlength="16" pattern="[A-Za-z0-9_]+">
```

При отправке формы браузер проверяет поля и не отправляет невалидные: показывает пузырёк «Заполните это поле» или «Введите адрес электронной почты». Это работает без единой строчки JavaScript.

- `required` — поле не может быть пустым.
- `type="email"`, `type="url"` — проверка формата встроена в сам тип.
- `minlength` / `maxlength` — длина текста в символах. Нюанс: `minlength` срабатывает, только если пользователь что-то ввёл, — совершенно пустое поле им не поймать, для этого есть `required`.
- `min` / `max` — границы для `type="number"` и дат.
- `pattern` — регулярное выражение для текста поля.
- `title` на поле — текст подсказки, который браузер покажет вместе с сообщением об ошибке.

## pattern пишется без косых черт

`pattern` — это **тело** JavaScript-регулярного выражения, без ограничителей `/…/` и без флагов:

```html
<input name="code" pattern="[0-9]{4}" title="Четыре цифры">
```

`pattern="/[0-9]{4}/"` — классическая ошибка: браузер будет искать текст, буквально начинающийся и заканчивающийся косой чертой. Якоря `^` и `$` писать тоже не нужно — браузер сам оборачивает выражение в `^(?:…)$`, то есть требует совпадения со **всем** значением поля.

## Состояния полей в CSS

У каждого поля есть псевдоклассы `:valid` и `:invalid`:

```css
input:invalid { border-color: #e11d48; }
input:valid   { border-color: #16a34a; }
```

Ловушка: пустое поле с `required` невалидно **до первого касания**, и вся форма встречает пользователя красной. Мягче ведёт себя `:user-invalid` (поддерживается современными браузерами): он срабатывает только после попытки ввода или отправки формы.

Проверку можно отключить: атрибут `novalidate` на `form` или `formnovalidate` на кнопке. Это нужно не чтобы «отправить что попало», а когда валидацию и сообщения об ошибках полностью рисует JavaScript.

## Почему сервер проверяет всё заново

Клиентскую проверку обходят одной командой:

```bash
curl -X POST https://example.com/signup -d "age=-5&mail=не-почта"
```

Ни страницы, ни браузера, ни `required` — голый HTTP-запрос. Так может сделать скрипт, бот или любопытный пользователь, открывший DevTools. Данные формы редактируются до отправки: подставить `age=-5`, удалить поле, изменить `type="hidden"` — можно всё.

Отсюда правило, которое действует всегда: **валидация в браузере — забота о пользователе, валидация на сервере — единственная защита.** Сервер повторно проверяет формат, границы, длину и обязательность, а в ответе возвращает ошибки, которые фронтенд покажет у нужных полей. HTML-атрибут `required` не защищает вашу базу данных ни от чего.

## Типичные ошибки

- **`pattern="/[0-9]{4}/"`** — с косыми чертами и флагами.
- **Сервер доверяет браузеру**, «потому что в форме стоит required».
- **`:invalid` без смягчения** — красная форма на ещё не тронутой странице.
- **Сообщение об ошибке только в `alert`** — оно исчезает; ошибка должна оставаться рядом с полем, чтобы её можно было прочитать и исправить.
