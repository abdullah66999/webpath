## Аннотация — подсказка, а не проверка

Аннотация типа (type annotation) объявляет, какие данные ожидаются в параметре и что вернёт функция:

```python
def discount(price: float, percent: float) -> float:
    return price * (1 - percent / 100)

total: float = discount(1000, 15)
```

Главное, что нужно понять сразу: **интерпретатор аннотации не исполняет**. Это метаданные для людей и инструментов. Код ниже отработает без единой ошибки:

```python
def double(x: int) -> int:
    return x * 2

print(double("5"))   # 55 — строка «прошла» в функцию, объявленную для int
```

Python лишь сохраняет аннотации рядом с функцией. Проверяют их **статические анализаторы** — в первую очередь mypy — и редактор кода.

## Зачем тогда это нужно

- **Ошибки ловятся до запуска.** mypy видит `double("5")` и ругается на этапе проверки, а не в три часа ночи на продакшне.
- **Редактор становится умнее.** Знает, что `user.name` — строка, и подсказывает её методы; автодополнение перестаёт быть гаданием.
- **Функция документирует себя.** Сигнатура `def transfer(src: str, dst: str, amount: Decimal) -> bool` заменяет абзац комментариев.
- **Рефакторинг становится безопаснее.** Поменяли тип — анализатор покажет все места, которые сломались.
- **Фреймворки читают аннотации сами.** FastAPI строит по ним валидацию запросов: там аннотации уже не подсказка, а рабочий инструмент.

## Встроенные типы и коллекции

Для контейнеров тип элемента пишется в квадратных скобках:

```python
names: list[str] = ["Аня", "Марк"]
prices: dict[str, float] = {"чай": 320.0, "кофе": 900.0}
point: tuple[int, int] = (10, 20)

def total(prices: list[float]) -> float:
    return sum(prices)
```

Функции аннотируются так: параметры — после двоеточия, возвращаемое значение — после `->`. У функции без возврата пишут `-> None`.

## Optional и Union: «или None»

Функции часто возвращают `None` в особом случае. Аннотация обязана это признавать — через `Optional` из модуля `typing`:

```python
from typing import Optional

def find_user(names: list[str], target: str) -> Optional[str]:
    for name in names:
        if name == target:
            return name
    return None
```

`Optional[str]` означает ровно «`str` **или** `None`» — то же самое, что `Union[str, None]` или современный синтаксис `str | None` (Python 3.10+). Никакого «необязательного параметра» здесь нет: необязательность задаётся значением по умолчанию, это другая история.

Зачем это нужно: увидев `Optional[str]` в возвращаемом типе, mypy потребует проверить результат на `None` перед использованием — и класс «поймал `None` вместо строки, `AttributeError`» исчезает из программы ещё до запуска.

## mypy вкратце

mypy — статический анализатор: он **не запускает** код, а разбирает его и сверяет типы.

```text
$ mypy calc.py
calc.py:5: error: Argument 1 to "discount" has incompatible type "str"; expected "float"
Found 1 error in 1 file (checked 1 source file)
```

Ставится как обычный пакет (`pip install mypy`), запускается по файлу или папке. Начинать стоит с собственного нового кода: аннотировать свежую функцию и прогонять mypy перед коммитом. Аннотировать весь старый проект за один вечер не выйдет и не нужно — mypy проверяет только то, что размечено, и спокойно соседствует с неразмеченным кодом.

## Частые ошибки

- Считать аннотацию проверкой: `def f(x: int)` **не запретит** передать строку — в рантайме не произойдёт ничего.
- Написать `-> str` у функции, которая иногда возвращает `None`, — нужен `Optional[str]`.
- Принять `Optional[str]` за «параметр можно не передавать» — за это отвечает значение по умолчанию, а не аннотация.
- Ждать, что mypy найдёт ошибки в неразмеченном коде: без аннотаций проверять нечего.
