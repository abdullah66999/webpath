## Flask — микрофреймворк

Flask делает две вещи: сопоставляет URL с функциями Python и превращает то, что функция вернула, в HTTP-ответ. Всё остальное — базы данных, формы, авторизацию, админку — вы добавляете сами или берёте из расширений. Поэтому его называют микрофреймворком (microframework): ядро маленькое, границы приложения определяете вы.

Альтернатива — Django, где всё уже есть и решение принято за вас. Начинать с Flask полезно именно потому, что вы руками собираете то, что в Django спрятано.

## Установка в виртуальное окружение

Ставить пакеты в глобальный Python — плохая привычка: проекты начнут конфликтовать версиями. Для каждого проекта создают **виртуальное окружение** (virtual environment) — отдельную папку со своим набором пакетов.

```bash
mkdir hello-flask && cd hello-flask
python -m venv .venv

# Windows
.venv\Scripts\activate
# macOS и Linux
source .venv/bin/activate

pip install flask
pip show flask
```

В приглашении терминала появится префикс `(.venv)` — значит, окружение активно. Выход из него — команда `deactivate`.

Файл приложения **не должен называться `flask.py`**: `import flask` подхватит ваш же файл, и вы получите непонятную ошибку импорта.

## Минимальное приложение

```python
from flask import Flask

app = Flask(__name__)


@app.route("/")
def index():
    return "Привет, это мой первый бэкенд"


if __name__ == "__main__":
    app.run()
```

По частям:

- `Flask(__name__)` создаёт объект приложения. `__name__` нужен, чтобы Flask понял, от какого файла считать пути к шаблонам и статике.
- `@app.route("/")` — декоратор, который регистрирует функцию как обработчик пути `/`. Функцию-обработчик называют **представлением** (view function).
- `return "..."` — строка становится телом ответа с `Content-Type: text/html`.
- `if __name__ == "__main__"` запускает сервер только когда файл исполняют напрямую, а не импортируют.

По умолчанию `app.run()` слушает `127.0.0.1:5000` — только ваш компьютер. Чтобы видеть сервер с телефона в той же сети, запускают `app.run(host="0.0.0.0")`. Порт меняют через `app.run(port=8000)`.

## app.run — это сервер разработки

Внутри `app.run()` поднимается Werkzeug — отладочный сервер. Flask запускает его в многопоточном режиме и печатает каждый запрос в терминал. На нагрузку он не рассчитан: в продакшне приложение отдают через gunicorn или uWSGI, а `app.run()` не вызывают вообще.

## debug=True: удобно и смертельно

Режим отладки включает три вещи: автоперезапуск при сохранении файла, понятную страницу с ошибкой и трассировкой, и **интерактивную консоль Python прямо в браузере**.

```python
app.run(debug=True)    # только на своём компьютере
```

Консоль защищена PIN-кодом, но он вычисляется из параметров окружения, которые атакующий часто может прочитать или подобрать. Поэтому формулировка здесь жёсткая: **`debug=True` на боевом сервере — это удалённое выполнение кода.** Не «не рекомендуется», а нельзя. В продакшне режим задают переменной окружения, и по умолчанию он выключен.

## Типичная ошибка: print вместо return

```python
@app.route("/")
def index():
    print("Привет, это мой первый бэкенд")   # уйдёт в терминал, а не в браузер
```

Функция ничего не вернула, Flask получит `None` и ответит ошибкой `500`. В браузер попадает только то, что вернули через `return`.
